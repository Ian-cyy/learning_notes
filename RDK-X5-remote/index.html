    一核心概念速查

    项目SSHVNC
    本质网络通信协议（Secure Shell）网络通信协议（Virtual Network Computing）
    默认端口225900（:0 会话）/ 5901（:1 会话）

    客户端位置Windows（MobaXterm / PowerShell / CMD）Windows（MobaXterm VNC / RealVNC Viewer）
    核心能力文字命令行 + 加密隧道；可 X11 转发单个 GUI 窗口传输整套完整桌面画面（截图流）

    二Windows 端常用命令（PowerShell / CMD 原生，不用 MobaXterm）

    2.1 ping 测试网络连通性

    powershellping 192.168.193.118
    • 正常：收到回复，显示延迟时间
    • 异常：请求超时 = 网络不通，检查是否同一局域网、板子是否开机
    • 前提：电脑和 RDK-X5 必须连同一个局域网（同手机热点 / 同路由器）

    2.2 Windows 原生 SSH 连接（PowerShell 推荐）

    powershellssh sunrise@192.168.193.118
    • sunrise = 板子用户名
    • 192.168.193.118 = 板子 IP 地址
    • 首次连接提示 Are you sure you want to continue connecting?，输入 yes 回车
    • 然后输入板子用户密码（输入时屏幕不显示字符，正常），回车

    2.3 指定端口 SSH（如果改了默认 22 端口）

    powershellssh -p 2222 sunrise@192.168.193.118

    2.4 SSH 带 X11 转发（跑 rviz2 / rqt 用）

    powershellssh -X sunrise@192.168.193.118
    ⚠ 注意Windows 原生 PowerShell 不带 X Server，需要安装 VcXsrv / Xming；MobaXterm 自带 X11 转发，直接用更方便。

    2.5 查看 Windows 本机 IP

    powershellipconfig

    找 无线局域网适配器 WLAN 下的 IPv4 地址，确认和板子在同一网段。

    2.6 查看板子 IP 是否在线（扫描局域网）

    powershellarp -a

    列出同一局域网所有设备的 IP 和 MAC 地址，可用来找板子 IP。

    四本次 VNC 最终成功方案（完整配置记录）

    4.1 方案选型结论

    方案结果原因
    TigerVNC + GNOME 桌面❌ 失败，报 Oh no! 崩溃GNOME-Shell 不兼容纯软件虚拟显卡 Xvnc
    TigerVNC + XFCE 桌面⚠️ 可用，但不是原版桌面界面换成 XFCE，所有命令/ROS 不受影响
    x11vnc + lightdm + dummy 虚拟显卡✅ 成功，原版 GNOME 桌面系统本身先跑起 Xorg :0 会话，x11vnc 抓取已有画面
    ⚠ 关键踩坑

    RDK-X5 官方镜像用的显示管理器是 lightdm，不是 gdm3。网上很多 PC 教程默认 gdm3，直接套用会失败。不要安装 gdm3，装了反而破坏环境。

    4.2 已安装/配置的组件清单

    组件作用状态
    lightdm显示管理器，启动 Xorg :0 图形会话系统自带，active(running)
    x11vncVNC 服务端，抓取 :0 画面通过 5900 端口对外系统自带，已 enable + start
    xserver-xorg-video-dummy-hwe-18.04虚拟显卡驱动，无头无 HDMI 时欺骗显卡输出已安装
    xserver-xorg-core-hwe-18.04Xorg 核心组件（dummy 驱动依赖）已安装
    /etc/.vnc/passwdVNC 登录密码文件（root 创建）已配置
    /etc/X11/xorg.conf.d/xorg.confdummy 虚拟显卡配置文件已创建
    3 个原 xorg 配置文件重命名为 .disable 后缀，避免冲突已禁用

    4.3 完整配置步骤（可复现）

    步骤 1：确认 lightdm 运行状态

    bashsystemctl status lightdm
    预期active (running)，且能看到 /usr/lib/xorg/Xorg -core :0 进程。

    步骤 2：设置 x11vnc 密码（必须 root 权限）

    bashsudo -i
vncpasswd /etc/.vnc/passwd
# 输入两次操作密码
# Would you like to enter a view-only password? 输入 n
exit
    ⚠ 注意Linux 密码输入时屏幕不显示任何字符，不是没输入上，直接敲完回车。

    步骤 3：启用系统自带 x11vnc 服务

    bashsudo systemctl daemon-reload
sudo systemctl enable x11vnc.service
sudo systemctl start x11vnc.service
systemctl status x11vnc.service
    预期active (running)，监听 5900 端口。出现两个 x11vnc 进程属于该镜像正常现象。

    步骤 4：安装 dummy 虚拟显卡驱动

    bashsudo apt update
sudo apt install xserver-xorg-core-hwe-18.04 xserver-xorg-video-dummy-hwe-18.04 -y

    步骤 5：禁用原有冲突的 Xorg 配置文件

    bashsudo mv /etc/X11/xorg.conf.d/xorg_dsi_ignore.conf /etc/X11/xorg.conf.d/xorg_dsi_ignore.conf.disable
sudo mv /etc/X11/xorg.conf.d/10-disable-screensaver.conf /etc/X11/xorg.conf.d/10-disable-screensaver.conf.disable
sudo mv /etc/X11/xorg.conf.d/1-resolution.conf /etc/X11/xorg.conf.d/1-resolution.conf.disable

    步骤 6：创建 dummy 虚拟显卡配置文件

    bashsudo nano /etc/X11/xorg.conf.d/xorg.conf

    粘贴以下完整内容：

    confSection "Device"
        Identifier "dummy_videocard"
        Option "NoDDC" "true"
        Option "IgnoreEDID" "true"
        Driver "dummy"
        VideoRam 524288
EndSection
Section "Monitor"
        Identifier "dummy_monitor"
        Modeline "1920x1440" 69.47 1920 1960 2152 2384 1440 1441 1444 1457
        Modeline "1920x1200" 26.28 1920 1952 2048 2080 1200 1229 1231 1261
        Modeline "1920x1080" 23.53 1920 1952 2040 2072 1080 1106 1108 1135
        Modeline "1024x600_60.00"  49.00  1024 1072 1168 1312  600 603 613 624
        HorizSync   5.0 - 1000.0
        VertRefresh 5.0 - 1000.0
EndSection
Section "Screen"
        Identifier "dummy_screen"
        Device "dummy_videocard"
        Monitor "dummy_monitor"
        DefaultDepth 24
        SubSection "Display"
                Depth 24
                Modes "1920x1440" "1920x1200" "1920x1080" "1024x600_60.00"
                Virtual 1920 1440
        EndSubSection
EndSection

    Ctrl+O 保存 → 回车 → Ctrl+X 退出。

    步骤 7：重启图形服务 + 重启板子

    bashsudo systemctl restart lightdm
sudo reboot

    步骤 8：Windows 端 VNC 连接

    • MobaXterm → Session → VNC
    • Remote hostname：192.168.193.118
    • Port：5900（不是 5901！）
    • 不勾选 SSL tunneling
    • 输入 vncpasswd 设置的密码

    4.4 修改 VNC 桌面分辨率

    编辑 /etc/X11/xorg.conf.d/xorg.conf，三个关键点：

    1. Modeline：该分辨率的时序参数（不能乱写，网上搜对应分辨率的 Modeline）
    2. Modes：写在最前面的分辨率优先使用
    3. Virtual：虚拟桌面画布，必须 ≥ 使用的分辨率

    示例：改成 1280×720（VNC 更流畅，推荐）

    confSection "Device"
        Identifier "dummy_videocard"
        Option "NoDDC" "true"
        Option "IgnoreEDID" "true"
        Driver "dummy"
        VideoRam 524288
EndSection
Section "Monitor"
        Identifier "dummy_monitor"
        Modeline "1280x720" 12.42 1280 1328 1440 1472 720 741 743 757
        Modeline "1920x1080" 23.53 1920 1952 2040 2072 1080 1106 1108 1135
        HorizSync   5.0 - 1000.0
        VertRefresh 5.0 - 1000.0
EndSection
Section "Screen"
        Identifier "dummy_screen"
        Device "dummy_videocard"
        Monitor "dummy_monitor"
        DefaultDepth 24
        SubSection "Display"
                Depth 24
                Modes "1280x720" "1920x1080"
                Virtual 1280 720
        EndSubSection
EndSection
    ⚠ 重要保存后必须重启图形服务生效：
    bashsudo systemctl restart lightdm

    五遇到的问题及解决方案汇总

    问题 1：TigerVNC 连接后报 Oh no! Something has gone wrong

    • 原因：GNOME-Shell 不兼容 TigerVNC 的纯软件虚拟显卡（Xvnc），GNOME 桌面崩溃
    • 解决：放弃 TigerVNC + GNOME 组合，改用 x11vnc + lightdm + dummy 方案（即本文第四章）

    问题 2：/etc/gdm3/custom.conf 文件是空的

    • 原因：RDK-X5 官方镜像根本没有安装 gdm3，用的是 lightdm 显示管理器
    • 解决：不要去改 gdm3 配置，直接用 lightdm；不要安装 gdm3

    问题 3：Unit gdm3.service could not be found

    • 原因：同上，系统没有 gdm3
    • 解决：确认 lightdm 存在并运行：systemctl status lightdm

    问题 4：vncpasswd 时报 123456: command not found

    • 原因：敲完 vncpasswd /etc/.vnc/passwd 后没有等密码提示，直接手动敲了密码，bash 把密码当成命令执行
    • 解决：先敲命令回车，等出现 Password: 提示后再输入密码（输入时屏幕不显示字符）

    问题 5：vncpasswd 误选了 view-only password（输入了 y）

    • 原因：操作失误
    • 解决：按 Ctrl+C 终止当前交互，重新执行 vncpasswd /etc/.vnc/passwd，view-only 选 n

    问题 6：VNC 连接黑屏 / 灰屏

    • 原因：板子无头无 HDMI，显卡没有输出画面；或 dummy 驱动配置错误
    • 解决：
      1. 确认 dummy 驱动已安装：dpkg -l | grep dummy
      2. 确认 /etc/X11/xorg.conf.d/xorg.conf 配置正确
      3. 重启图形服务：sudo systemctl restart lightdm
      4. 查看 Xorg 日志排查：cat /var/log/Xorg.0.log | grep -i error

    问题 7：SSH 连接报 Network error: Connection timed out

    • 原因：板子正在重启（执行了 sudo reboot），或网络不通
    • 解决：等待 40~60 秒板子完全启动后重连；检查电脑和板子是否同一局域网

    问题 8：x11vnc 服务出现两个进程

    • 原因：该镜像 x11vnc.service 的 -loop 参数导致，属于已知正常现象
    • 解决：不用管，不影响功能

    问题 9：VNC 窗口内 Ctrl+Alt+T 打不开终端

    • 原因：VNC 快捷键被 Windows 系统拦截
    • 解决：桌面空白处右键 → Open Terminal，或在 VNC 菜单里发送快捷键

    问题 10：修改 xorg.conf 后 VNC 分辨率没变

    • 原因：只重启了 x11vnc，没有重启 lightdm（Xorg 配置由 lightdm 加载）
    • 解决：sudo systemctl restart lightdm

    六WiFi 热点 AP 模式配置（RDK-X5 自己开热点）

    6.1 核心前提

    • RDK-X5 的 WiFi 网卡不支持 STA（连别人 WiFi）和 AP（自己开热点）同时并发，二选一
    • 开启 AP 后，板子断开当前 WiFi，当前 SSH/VNC 连接必然断开（正常现象）
    • 开启 AP 后板子没有外网，只是本地局域网，SSH/VNC/ROS2 通信不受影响
    • 板子 AP 模式下固定 IP：192.168.4.1

    6.2 安全切换流程（无头环境）

    1. 当前连手机热点、SSH 正常时，提前把 AP 所有配置文件全部写好（只配置，不启动）
    2. 确认配置无误后，执行启动 AP 的命令 → 旧 SSH 断开（预期）
    3. Windows 右下角手动断开手机热点，连接 RDK-X5 的新热点
    4. Windows 连上板子热点后，新建 SSH 会话，IP 改成 192.168.4.1，重新连接
    5. VNC 同样用 192.168.4.1:5900

    6.3 图形界面方式开热点（推荐，VNC 已可用）

    VNC 进入 GNOME 桌面：

    1. 右上角 WiFi 图标 → Wi-Fi Settings
    2. 点右上角 ➕ → Wi-Fi (shared)
    3. 填写 SSID（如 RDK-X5）、密码（至少 8 位）
    4. 保存并开启 → VNC 断开（正常）
    5. Windows 切 WiFi 连 RDK-X5 → 用 192.168.4.1 重连 SSH/VNC

    6.4 命令行方式开热点

    bash# 1. 安装依赖
sudo apt update
sudo apt install hostapd isc-dhcp-server -y
# 2. 创建热点配置
sudo nano /etc/hostapd.conf

    粘贴：

    confinterface=wlan0
driver=nl80211
ssid=RDK-X5
hw_mode=g
channel=6
ieee80211n=1
wpa=2
wpa_key_mgmt=WPA-PSK
wpa_passphrase=12345678
wpa_pairwise=CCMP
rsn_pairwise=CCMP
    bash# 3. 配置 DHCP（自动给连入设备分配 IP）
sudo nano /etc/dhcp/dhcpd.conf

    末尾添加：

    confsubnet 192.168.4.0 netmask 255.255.255.0 {
range 192.168.4.2 192.168.4.100;
option routers 192.168.4.1;
option domain-name-servers 8.8.8.8;
}
    bash# 4. 设置 wlan0 静态 IP 并启动热点（执行后旧连接断开）
sudo ifconfig wlan0 192.168.4.1 netmask 255.255.255.0 up
sudo hostapd -B /etc/hostapd.conf
sudo systemctl start isc-dhcp-server

    6.5 从 AP 切回 STA（连手机热点）

    bashsudo pkill hostapd
sudo systemctl stop isc-dhcp-server
sudo systemctl restart NetworkManager

    然后正常搜索 WiFi 连手机热点，SSH 用原来的 IP 重连。

    6.6 两种组网对比

    组网方式板子角色板子有外网吗适用场景
    手机热点（STA 模式）WiFi 客户端✅ 有开发阶段，需要 apt 下载、git clone
    RDK-X5 开热点（AP 模式）无线路由器❌ 无比赛现场，独立局域网，ROS2 通信更稳定
    💡 建议开发下载代码用手机热点；现场调试机器人/跑 ROS2 切 RDK 的 AP 热点。

    八日常使用最佳实践

    1. 主力开发用 SSH：编译、启动 ROS、改配置、重启板子，全部 SSH 完成
    2. rviz2 / rqt 走 MobaXterm SSH 的 X11 转发，不要放到 VNC 窗口运行（性能差）
    3. VNC 仅用于：OpenCV 图像预览（cv2.imshow）、文件浏览、简单图形设置
    4. VNC 内打开终端：桌面空白处右键 → Open Terminal（Ctrl+Alt+T 大概率失效）
    5. 板子重启后：VNC 是开机自启的，不需要手动敲命令，等 40~60 秒直接连 IP:5900
    6. Micro-B（USB）口：只在烧录系统镜像或应急抢救时用，日常开发不用插
    7. 修改 xorg.conf 后：必须 sudo systemctl restart lightdm，只重启 x11vnc 不生效
    8. 比赛现场：提前在家把 AP 热点配置写好测试一遍，不要到现场第一次切
