STM32G431 串口 IAP 在线升级系统

基于 STM32G431RBT6 的串口在线升级（IAP, In-Application Programming）系统。板子上电后由 Bootloader 决定进入 App 或进入升级模式，通过 USART2（可外接蓝牙/2.4G 无线模块）接收 PC 上位机发送的固件，写入 Flash 后跳转运行。

总项目总览

README.md · 根目录总览文档

特性

  • 无线 OTA：USART2(PA2/PA3) 外接蓝牙 / 2.4G 模块，隔空升级不用接线
  • 可靠传输：逐帧 CRC16 + ACK/NAK 重传 + 整包校验，通过才允许跳转
  • 分层可移植：核心逻辑(iap.c)与硬件适配(iap_port.c)分离，换 MCU 只改移植层
  • 指示灯提示：BL 模式下 LED 闪烁，直观确认状态

开发平台

本工程面向 蓝桥杯嵌入式竞赛开发板（CT117E）：

资源配置
主控STM32G431RBT6 (Cortex-M4, 128KB Flash, 32KB RAM)
屏幕2.4 寸 TFT LCD（并行接口）
LEDPC8~PC15 + PD2 锁存
按键PB0 等
串口USART1(PA9/10, 板载USB) + USART2(PA2/3, 引出)

本项目用到的板载资源USART2(PA2/PA3, OTA 串口)、PB0(进 BL 按键)、LED(BL 模式指示)。

USART2PA2(TX) / PA3(RX)115200引出排针，外接 蓝牙 / 2.4G 无线串口模块，用于 OTA 在线升级

2工作原理

上电复位
  │
  ├─ 未按按键 ───────────► 跳转到 App 运行
  │                          (若 App 无效则驻留 BL, 作为安全兜底)
  │
  └─ 按住按键(PB0) ──────► 进入 Bootloader 升级模式
                           等待上位机: 握手→擦除→数据→校验→跳转
  • Bootloader 占用 Flash 前 16KB，负责引导 + 串口升级
  • App 从 0x08004000 开始，正常运行业务逻辑
  • 升级通过 USART2 (PA2/PA3) 进行（可外接蓝牙/2.4G 无线模块实现无线 OTA），协议带 CRC 校验和 ACK/NAK 重传

内存分布

区域起始地址结束地址大小用途
Bootloader0x080000000x08003FFF16KB引导 + IAP 升级代码
App0x080040000x0801FFFF112KB应用固件
RAM0x200000000x20007FFF32KB数据区
⚠ 注当前为 BL 单区 + App 单区，未实现 A/B 双备份(升级失败无回滚)。

帧格式:  AA 55  CMD  LEN_LO  LEN_HI  DATA[0~256]  CRC_LO  CRC_HI
CMD含义
0x01握手
0x02擦除 App 区
0x03写数据块(≤256B)
0x04结束 + 整包 CRC 校验

  • 波特率: 115200, 8N1

子Bootloader 固件详解与移植指南

bootloader/README.md

STM32G431RBT6 的 Bootloader（蓝桥杯嵌入式 CT117E 开发板），占用 Flash 前 16KB。负责引导 App，并通过 USART2 (PA2/PA3) 实现串口在线升级（可接蓝牙/2.4G 无线模块做无线 OTA）。

系统配置

  • 主时钟: HSI 16MHz(不使用 HSE/PLL)
  • 串口: USART2, 115200, 8N1, 中断优先级 6（USART1 优先级 5 用于板载 USB）
  • Flash: 页大小 2KB, 编程粒度 64bit 双字

内存分区

区域地址范围大小
Bootloader0x08000000 ~ 0x08003FFF16KB (scatter 里 0x4000)
App0x08004000 ~ 0x0801FFFF112KB

分区依据 MDK-ARM/bootloader/bootloader.sct:

LR_IROM1 0x08000000 0x00004000   ← Bootloader 只占 16KB

App 区从 0x08004000 开始，对应 iap.h 里的 IAP_APP_BASE。

1启动流程

main():
  HAL_Init() → SystemClock_Config() → MX_GPIO_Init()
  → MX_USART1_UART_Init() → MX_USART2_UART_Init()
    │
    ├─ IAP_Port_IsButtonPressed() 为假(没按键) → IAP_JumpToApplication() 跳 App
    │
    └─ 按键按下 → IAP_Init() → IAP_Port_RxStart() → while(IAP_Process())
                  ↑ 进入升级模式: LED 闪烁, 等待上位机

main.c 里的固定模板（USER CODE 2，换芯片不用改）：

cled_all_off();
if (!IAP_Port_IsButtonPressed())
    IAP_JumpToApplication();
IAP_Init();
IAP_Port_RxStart();
while (1) { IAP_Process(); /* LED 闪烁 */ }

跳转流程（iap.c 的 IAP_JumpToApplication）:

  1. 检查 App 起始地址第一个字(SP)是否在 RAM 范围
  2. 关中断 → 设 SCB->VTOR = 0x08004000 → 切换 MSP → 恢复中断
  3. 跳转到 App 复位入口
⚠ 注意跳转前必须 __enable_irq()，否则 App 中断全关(会卡死在 HAL_Delay)。

2通信协议

帧格式

字节:   0     1     2    3    4    5...5+LEN-1   5+LEN    6+LEN
      ┌─────┬─────┬────┬─────┬─────┬─────────────┬────────┬────────┐
      │ 0xAA│ 0x55│ CMD│LEN_LO│LEN_HI│   DATA      │CRC_LO  │ CRC_HI │
      └─────┴─────┴────┴─────┴─────┴─────────────┴────────┴────────┘
        帧头    命令  数据长度(小端,≤256)  数据      CRC16(小端)

命令

CMD含义DATA 内容回复
0x01握手空ACK
0x02擦除 App 区空ACK/NAK
0x03写数据块≤256B 数据ACK/NAK
0x04结束总长度(4B)+整包CRC(2B)ACK/NAK
0x05跳转 App空ACK(校验通过才放行)

回复: 0x06=ACK, 0x15=NAK。

CRC16

  • 算法: CRC16-CCITT, 多项式 0x1021, 初值 0xFFFF
  • 每帧对"帧头~DATA"做 CRC；整包对所有数据字节累加做 CRC

升级时序

PC 上位机                     Bootloader
    │                             │
    ├── 握手(0x01) ──────────────►│ 回 ACK(进 BL 先发 "BL\r\n")
    ├── 擦除(0x02) ──────────────►│ 按页擦 App 区, 回 ACK
    ├── 数据帧(0x03) ◄─ACK────────┤ 每 8B 一个双字写 Flash, 回 ACK
    │     ... 循环 256B/帧 ...
    ├── 结束(0x04, 带整包CRC) ───►│ 补写余数+整包校验, 回 ACK
    ├── 跳转(0x05) ─────────────►│ 校验通过才 ACK, 然后跳转 App
    │                             │

4移植指南（换 STM32 或换工程）

步骤

  1. 复制 IAP/ 文件夹到新工程，加入 Keil 工程并添加 ../IAP 到 include 路径
  2. 改 iap.h 三个宏:
c#define IAP_APP_BASE        0x08004000UL   /* App 起始地址(和 BL 分区对应) */
#define IAP_APP_END         0x08020000UL   /* App 结束地址 = 芯片 Flash 上限 */
#define IAP_FLASH_PAGE_SIZE 2048UL         /* 芯片 Flash 页大小 */
  1. 改 iap_port.c 顶部:
c#define IAP_UART  huart2   /* 改成你的 UART 句柄(OTA 用) */

以及按键引脚、LED 等硬件适配。

  1. CubeMX 配置: 重配 USART 引脚、波特率(和上位机一致)、按键引脚
  2. 若 Flash 擦除/编程 API 不同(如 F4 扇区、H7 块): 改 iap.c 里的 iap_erase_app 和双字编程部分
  3. 上位机: iap_tool/iap_upload.py 里把 BAUD 改成和固件一致

5常见问题

  • 握手失败: 确认板子已进 BL(按住按键上电,LED 闪烁)、串口号/波特率正确、无线模块已配对
  • 用串口助手先发过握手会残留 BL\r\n: 上位机脚本在回车后会 reset_input_buffer() 清掉，无影响
  • App 起不来: 检查跳转前是否 __enable_irq(); 检查 App 是否链接在 0x08004000
  • 超 16KB: Bootloader 代码 + 库过大，需扩大分区(改 scatter + iap.h + App 地址)
  • 无线 OTA 不稳定: 降低波特率或用有线 USB 转 TTL 排查

子PC 上位机工具（iap_upload.py）

iap_tool/README.md

Python 编写的串口 IAP 烧录工具，通过 USART2 (PA2/PA3) 与 Bootloader 通信（可接蓝牙/2.4G 无线模块做无线 OTA），把 App 的 .bin 文件写入芯片。

环境依赖

  • Python 3.x
  • pyserial 库

安装 pyserial:

pip install pyserial

如果 pip 不在 PATH，用完整路径:

D:\Python\python.exe -m pip install pyserial

使用方法

python iap_upload.py <bin文件绝对路径> [串口号]

示例（Windows，Python 完整路径）：

D:\Python\python.exe iap_upload.py D:/project/app/app.bin COM18
  • 第一个参数: App 固件 .bin 的绝对路径(路径含空格用引号包起来)
  • 第二个参数(可选): 串口号; 不填则自动列出可用串口供选择
  • 不传 bin 参数时会交互式询问路径（运行后粘贴即可，可用绝对路径）

操作流程

  1. 运行脚本，输入/传入 bin 路径，选择串口
  2. 提示"请确保目标板已进入 Bootloader 模式..."
  3. 按住按键(PB0) → 上电 → 松手, 等 LED 连续闪烁(即已进 BL)
  4. 按回车开始烧录
  5. 等待输出 握手成功 → 擦除完成 → 进度 → 整包校验通过 → 已跳转 App
  6. 脚本自动延时 3 秒后退出（失败也会停留 3 秒便于查看）

接线

板子 OTA 串口是 USART2 (PA2/PA3):

板子 PA2(TX)  → 无线模块 RX
板子 PA3(RX)  → 无线模块 TX
GND            → GND(共地)
  • 无线 OTA: PA2/PA3 接蓝牙或 2.4G 无线串口模块，PC 端也接一个同款模块，即可隔空升级
    • 两个无线模块波特率都要设为 115200，且配对在同一通道/频段
    • 蓝牙需先配对连接；2.4G 模块需设置相同地址/通道
  • 有线调试: 板载 USART1(PA9/PA10) 通过 GD32→Type-C 连 DAPLink，用于烧录 Bootloader 本体和调试

1协议实现

帧格式

字节:   0     1     2    3    4    5...5+LEN-1   5+LEN    6+LEN
      ┌─────┬─────┬────┬─────┬─────┬─────────────┬────────┬────────┐
      │ 0xAA│ 0x55│ CMD│LEN_LO│LEN_HI│   DATA      │CRC_LO  │ CRC_HI │
      └─────┴─────┴────┴─────┴─────┴─────────────┴────────┴────────┘
        帧头    命令  数据长度(小端,≤256)  数据      CRC16(小端)

命令

CMD含义DATA期望回复
0x01握手空ACK
0x02擦除空ACK
0x03数据块≤256BACK
0x04结束总长(4B)+整包CRC(2B)ACK
0x05跳转空ACK

烧录流程

握手(0x01) → 擦除(0x02) → 数据帧(0x03, 每帧256B) → 结束(0x04, 带整包CRC) → 跳转(0x05)
  • 每发一帧等待回复: 0x06=ACK 继续, 0x15=NAK 或超时重发(最多 3 次)
  • CRC16-CCITT(0x1021, 初值 0xFFFF): 每帧校验 + 整包累加校验
  • 波特率 115200, 与固件一致

脚本函数

函数作用
crc16(data, init)CRC16-CCITT 计算，支持累加(传上次结果)
build_frame(cmd, data)组帧：头 + 命令 + 长度 + 数据 + CRC
send_wait(ser, frame)发一帧并等 ACK，超时/NAK 重发(最多3次)
pick_port()列出并选择可用串口

关键参数

参数值说明
BAUD115200波特率, 和固件 usart.c 一致
BLOCK256每帧数据字节数
MAX_RETRY3单帧最大重发次数

1与 Bootloader 的配合

中断向量表 (VTOR)

  • Bootloader 跳转前会设置 SCB->VTOR = 0x08004000
  • 因此 App 的 system_stm32g4xx.c 里 USER_VECT_TAB_ADDRESS 处于注释状态时也能正常工作（依赖 Bootloader 已设好 VTOR）
  • 若希望 App 自包含（不依赖 Bootloader），可在 system_stm32g4xx.c 里定义:
c#define USER_VECT_TAB_ADDRESS
#define VECT_TAB_OFFSET 0x4000

中断状态

  • Bootloader 跳转前会恢复全局中断（__enable_irq()），App 启动时中断状态与上电复位一致，无需额外处理

串口配置

串口引脚波特率用途
USART1App 工程自定义9600App 自身业务通信
USART2PA2/PA3115200Bootloader OTA 升级串口（App 不参与）
  • 两者是不同的 USART，引脚、波特率、用途互不冲突
  • 升级时由 Bootloader 使用 USART2，App 不参与

2使用 Bootloader 升级

1. 用 Keil5 生成 .bin

配置一条"编译后自动生成 bin"的命令：

  1. Keil 菜单 Options for Target → User 标签页
  2. 找到 After Build/Rebuild，勾选某一条 User Command
  3. 填入：
fromelf --bin -o "$L@L.bin" "#L"

4. 编译完成后，输出目录里自动生成 <工程名>.bin

命令解析

部分含义
fromelfARM 编译器自带的镜像转换工具
--bin输出原始二进制格式
-o "文件"指定输出文件名
$LKeil 变量：输出目录
@LKeil 变量：目标文件名（不含扩展名）
#LKeil 变量：链接产物 .axf 的完整路径
⚠ 若报错若报错 CreateProcess failed 或找不到 fromelf，说明它不在 PATH 里，改用完整路径：
"D:\004\51\ARM\ARMCC\Bin\fromelf.exe" --bin -o "$L@L.bin" "#L"
（路径以你实际安装位置为准）

2. 串口升级

python ..\iap_tool\iap_upload.py ..\national_competition_test_1\MDK-ARM\national_competition_test_1\national_competition_test_1.bin COM18
  1. 先把生成的 .bin 路径传给脚本（可换你自己的串口号）
  2. 按住按键(PB0)上电进入 Bootloader 模式，LED 闪烁
  3. 脚本提示后按回车，等待 握手成功 → 擦除完成 → 进度 → 整包校验通过 → 已跳转 App

详细说明见 ../iap_tool/README.md。

3注意事项

  • App .bin 大小不能超过 App 区(112KB)
  • App 链接地址固定为 0x08004000，不会覆盖 Bootloader 区(0x08000000~0x08003FFF)
  • 升级中途掉电/失败会导致 App 损坏（当前无 A/B 备份），需要重新进 BL 完整烧录
  • 重新编译后若地址配置变化，需重新烧录 Bootloader 并同步 App 地址
