一CPU vs GPU：两种"强"

⚠️ 反直觉的真相
不是 CPU 更强，而是两者"强"的地方不同。
CPUGPU
核心数少（4~64）多（几千~上万）
单核能力强、灵活、会判断弱、只会简单运算
擅长复杂逻辑、串行任务简单重复、海量并行
类比几个博士生几千个小学生
  • CPU 强在单打独斗、复杂任务（操作系统、开网页）。
  • GPU 强在人海战术、简单重复（给一亿像素上色）。
  • 没有谁"取代"谁，是分工不同。

二显卡通用计算（GPGPU）

洞察："给像素上色"和"做数学运算"本质一样——都是对海量数据做同一种简单计算。
  • GPU 本来只画图，但既然能算颜色，就能算矩阵、物理、AI。
  • 这就是 GPGPU（General-Purpose computing on GPU，GPU 通用计算）。
  • 一句话：GPU 从"只会画画的画工"，被改造成"什么数都能算的计算民工"。

为什么 AI 适合 GPU

  • 神经网络的 90% 时间在做矩阵乘加（如 4096×4096 相乘 = 几亿次"乘一下、加一下"）。
  • 每一次极简单、彼此独立 → 正好让几千个核心并行。
  • CPU 只有几十核，只能排队慢慢算，慢几十上百倍。
  • 后来英伟达又专门做了矩阵运算专用核心（Tensor Core），把这件事做到极致。

三CUDA：英伟达的护城河

3.1 CUDA 是什么

英伟达给自家 GPU 配的一整套软件工具包，包含：

  1. 语言：用 C/C++ 写 GPU 程序；
  2. 编译器：把代码编成 GPU 指令；
  3. 现成库（cuBLAS/cuDNN）：矩阵运算等拿来即用；
  4. 生态：教程、框架、人才全围着它转。
🚗 类比
硬件是发动机，CUDA 是驾驶系统 + 全套工具。没有 CUDA，GPU 就是用极其晦涩的底层指令去驱动的精密机器，门槛高到几乎没法用。

3.2 护城河的本质是"迁移成本"

  • 20 年积累：几百万行代码、库、教程、论文、课程全默认 CUDA。
  • 框架绑定：PyTorch / TensorFlow 底层默认 CUDA。
  • 网络效应：用的人越多 → 库越好 → 更多人用。
  • 关键：硬件可以追，20 年的生态没法一夜复制。英伟达卖的不只是卡，是"不用重写代码"。

3.3 2006/2007 年的远见：不是专门为了 AI

  • 2006/07 推出 CUDA，动机是 GPGPU（科学计算、物理模拟、金融），不是 AI。
  • 2012 AlexNet 用两块 GTX 580 训练夺冠，深度学习爆发，正好跑在 CUDA 上。
  • 2014 起英伟达才专门为 AI 加码：cuDNN、Tensor Core（2017 Volta）。
  • 远见是"GPU 是通用并行处理器"，不是"AI"——但通用性恰好是 AI 需要的。

3.4 和游戏驱动的区别

游戏驱动（图形）CUDA（计算）
干什么把 DirectX/OpenGL 变成"画像素"让你写代码让 GPU"算任意东西"
谁在用玩家 / 厂商开发者
灵活性固定管线通用编程
类比让显卡画画让显卡干活/算数

一块显卡两套本领：图形（打游戏）+ 计算（CUDA），都建立在同一硬件和底层驱动上。

四AMD 为什么没份

一句话：AMD 不是没做 AI 卡，而是"硬件能打、软件不跟"，又撞在 CUDA 护城河上。

时间线

时间事件
2006AMD 收购 ATI，同时做 CPU/GPU
2007 起英伟达全力押注 CUDA；AMD 重心在游戏显卡和 CPU
2016AMD 才推出对标 CUDA 的 ROCm（晚近 10 年）
2023/12发布 MI300X，硬件强悍、显存更大，正式冲 AI
2024~2026MI325X / MI350X / MI355X / MI400 陆续上，硬件追得紧

为什么还是没它的事

  1. 软件生态差距：ROCm 不稳、框架支持滞后，迁移成本高。
  2. 起步太晚：英伟达领先 10 年。
  3. 策略失误：长期把 GPU 当游戏业务。
  4. 中国不买账：也受出口管制，且不是国产。

现状

  • 主要在推理/价格敏感/备胎场景：微软、Meta、Oracle、xAI 少量采购 MI300/355X。
  • 公开统计口径不同，英伟达在数据中心 AI 加速器市场占据明显主导；AMD 等厂商份额通常为个位数到低两位数，具体年份和口径需查最新市场报告。
  • AMD 也走 HIP 兼容 CUDA 路线（能追，但永远是追兵）。

八TileLang 开源事件（9.30）

8.1 先澄清

  • 本文所说的"9/30"是指 2026/9/30 的仓库更新/公告时间。
  • DeepSeek 没开源整个 TileLang（TileLang 2025/1 已开源）。
  • 9/30 是 TileLang 正式支持华为昇腾 950 NPU，而这套昇腾后端主要由 DeepSeek 工程师开发并开源。
  • 类比：不是发布了 CMSIS，而是给 CMSIS 写了一个"昇腾移植层"并公开。

8.2 TileLang 是什么

  • 北大杨智团队 + 微软研究院发起，基于 Apache TVM。
  • 用 Python 写 GPU/NPU 高性能算子（GEMM、FlashAttention 等）。
  • 一份代码，编译到多家芯片：CUDA / ROCm / Metal / 昇腾。

8.3 和 CUDA 的关系

PyTorch
  ├─ 走英伟达 → CUDA → NVIDIA GPU
  └─ 走昇腾   → torch_npu → CANN → 昇腾 NPU

TileLang（跨芯片翻译层）
  ├─ 编到 CUDA   → NVIDIA GPU
  └─ 编到 Ascend → CANN → 昇腾 NPU
  • TileLang 和 CUDA 同一层，但跨芯片，是"想抽掉 CUDA 这层"的角色。
  • 在英伟达上是"生成 CUDA"，不是"取代 CUDA"。

8.4 开源规模（实测仓库）

  • 287 个相关文件、约 4 MB（代码约 3.3 MB，估计数万行）。
  • src/ascend/ 就 85 个 C++ 文件、~1.9 MB：codegen_pto.cc(292KB)、codegen_ascend.cc(147KB)、insert_sync.cc(104KB)、estimate_latency.cc(88KB)、layout_inference.cc(74KB)、auto_schedule.cc(53KB)…
  • 示例覆盖 DeepGEMM、FlashAttention（含反向）、FP8。
  • 测试 101 个文件。
  • 结论：完整后端移植，不是 demo。

8.5 用户分布

  • 产业侧高度集中在中国：华为昇腾、摩尔线程、沐曦、海光、燧原、算能均适配。
  • 旗舰用户 DeepSeek（V3.2-Exp 起用于模型研发）。
  • GitHub 页面抓取时约 7.9k star / 791 fork；这是随时间变化的社区指标。
  • 海外主要零散用于写 CUDA/AMD 算子。

8.6 意义

  1. 对 DeepSeek：供应链安全、降本、声誉。
  2. 对华为：白捡顶尖外援补 CANN 之上的适配。
  3. 对国产链：头部 AI 公司主动下场补生态，示范效应。
  4. 对 CUDA：长期威胁、短期有限。
  5. 对 TileLang：获得旗舰用户 + 关键后端，解决冷启动。
一次开源的本质是"用开源的方式给国产算力修路"——最大意义是信号和方向，不是短期撼动 CUDA。

九多卡与集群：分层互联

9.1 节点层级

1 张 GPU
  ↓ 8 张卡（典型）用 NVLink 连成一块 HGX 基板
1 个节点 = 1 台服务器（通常 8 卡，一个 OS 实例）
  ↓ 几十个节点装进机架(rack)
1 个机架
  ↓ 网络互联
1 个集群（几万 → 几十万张卡）
  • 节点 = 一台独立机器；一个机箱也可能塞多个节点。
  • 少数系统把 72 张卡（GB200 NVL72）连成一个 NVLink 域。

9.2 互连层级（互连版"存储层级"）

层级技术带宽规模
核心↔显存HBM~8 TB/s单卡
卡↔卡（机内）NVLink/NVSwitch数百 GB/s 到 TB/s 级取决于代际和拓扑
节点↔节点InfiniBand / RoCE通常低于机内互联取决于网卡、链路和交换机
CPU↔GPUPCIe~64 GB/s单机
💡 越近越快越贵、规模越小
这不是随便选的，是"距离/规模/成本"逼出来的。

9.3 NVLink vs PCIe

PCIe 5.0NVLink 5
性质通用硬件协议专用硬件协议
带宽~64 GB/s~1800 GB/s
谁用CPU↔GPU、通用扩展GPU↔GPU 专用
归属开放标准英伟达私有
  • NVSwitch：交换芯片，把很多 NVLink 连成"全互联"。
  • AMD 对应：Infinity Fabric（xGMI）；开放标准 UALink。
  • 节点间用 InfiniBand / RoCE（网络）。
  • 为什么分层：NVLink 距离短、连卡数有限、极贵；InfiniBand 能铺开几万节点。

9.4 共享内存原理

  • NVLink/NVSwitch 把多卡显存组成 统一内存池，可互相直接访问。
  • 例：GB200 NVL72 = 72 卡一个域，130TB 统一显存。
  • 注意：老游戏技术 SLI/CrossFire 不是共享内存（各用各的显存，只分帧）。

9.5 集群不是"一块超大 PCB"

  • 是分层互联：卡间 NVLink/NVSwitch，节点间 InfiniBand/RoCE，集群用交换机级联。
  • 几万卡 = 几万台服务器 + 大量交换机，不是一块巨型主板。
  • 带宽靠层级结构 + 并行策略（张量/流水线/数据并行），尽量把高频通信压在节点内。
  • 大数据集群的 PCIe 慢 → 节点内用 NVLink 绕开它。

最卡的那一步（按场景）

场景最卡原因
推理HBM 带宽（核心↔显存）每字都要重读全部权重，通常不跨节点
训练视并行策略而定，常见瓶颈是跨卡/跨节点同步卡数越多，通信占比越高，扩展效率下降

十一分布式算力与个人显卡出租

11.1 训练/推理集群能复用吗

  • 技术上一批卡既能训练也能推理（硬件一样）。
  • 实际做法：分池 + 混部 + 推理外包 三管齐下。
    • 分池：训练池 / 推理池。
    • 混部（co-location）：把推理塞进训练空闲期，提高利用率。
    • 推理外包：DeepSeek 模型由 20+ provider 一起服务。
  • 资源本质稀缺：给推理的卡就不能训练，是机会成本。

  • 笔记本 RTX 3060（通常为 6GB，具体视机型）显存小、散热和持续供电能力有限、收益不稳定，电费、折旧和设备损耗可能超过收入。

  • 结论：笔记本出租 ≈ 零钱，不是生意。

11.3 众包算力能当集群吗

  • 能众包"独立任务"（渲染、科学模拟），不能众包大模型训练。
  • 训练中的高频同步对带宽和延迟很敏感；家庭互联网与数据中心高速互联在带宽、延迟、稳定性上存在数量级差异。
  • "压缩梯度"（梯度压缩/量化/稀疏化/蒸馏）存在但有限，不能把互联网训练变成可行。
  • 大型训练必须靠数据中心级集群。

十三一句话总纲

CPU 管复杂逻辑，GPU 管海量重复；AI 正好是海量重复，于是 GPU 上位；而让 GPU 真正能用的 CUDA，顺理成章成了英伟达的护城河。国产芯片硬件追得快，但卡在软件生态（CANN/TileLang 正在补）。多卡集群是"分层互联"：越近越快越贵、规模越小。当前瓶颈不在算力，而在带宽（HBM + 互联）与 HBM/封装产能，国产额外卡在软件生态。
