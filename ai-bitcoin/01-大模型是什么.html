01 · 大模型是什么

本质是函数 → 参数是旋钮 → 训练是拧旋钮 → 推理是用函数 → 全程吃显存和算力

🗓 资料截止 2026/10/1 📦 系列第 1 篇 📝 10 章 👤 GitHub @Ian-cyy

一本质：大模型是一个巨大的函数

大模型（LLM）不是数据库，也不是"存答案的哈希表"，它更像：

一个用海量参数拟合出来的超级函数：输入文字 → 输出文字。
  • 参数（权重）不是"存好的答案"，而是几亿到几万亿个系数 / 旋钮。
  • 模型不是"查"出答案，而是"现算"出答案：每次都用同一套参数、根据你的输入实时计算。
  • 因此同一个问题每次结果几乎一样，不是因为查表，而是因为计算过程一样。

类比（逐个记牢）

类比对应
一个固定公式 f(x)=...模型参数固定
代入 x=3 去算输入你的问题
算出结果生成答案
公式固定，但每个 x 都要现算参数固定，但每个问题都要现算

关键推论

  • 参数固定 ≠ 答案固定：答案取决于输入。
  • 想枚举"所有输入→输出"当查表？可能输入近乎无限，存储装不下，所以只能学规律、现算——这就是"泛化"。

二从输入到输出：token 与计算流程

2.1 文字如何变成数字

"今天天气"
   ↓ 切分成 token（词块）：[今、天、天气]  （不同模型切法不同）
   ↓ 每个 token 映射成整数 ID：[1234, 5678, 9012]
   ↓ 每个 ID 变成一串数字（向量 / embedding）

2.2 生成一个字的完整流程

输入向量
  → 第 1 层：矩阵乘 + 注意力(Attention)
  → 第 2 层：矩阵乘 + 注意力
  → …（几十 ~ 上百层）
  → 输出向量
  → 转成"词表里每个词的概率"（softmax）
  → 按采样策略选出下一个 token："真"
  → 把这个字接回输入，重复，生成下一个字
💡 要点
  • 每生成一个 token 通常需要一次解码阶段的前向计算（forward pass）；"token"不一定等于一个汉字或一个单词。
  • 核心动作就是 "输入向量 × 权重矩阵"，一层层算下去。
  • 权重（参数）固定，输入每次都不同，所以每次都得算。
⚠️ 为什么推理也叫"自回归生成"
一个字一个字往外蹦，每蹦一个字都要重跑一遍网络。

三为什么它"能理解"，而不是"查表"

哈希表 / 数据库大模型
存什么输入→输出 的映射海量参数（系数）
怎么给答案查算
遇到没见过的问题查不到能"泛化"推断
存储需求要存下所有组合（不可能）固定大小，拟合规律

为什么不能是哈希表

  • 可能的句子是天文数字（近乎无限），不可能全部存下。
  • 模型改学语言的统计规律，把规律压缩进参数里，用有限的参数应对无限的输入。
⚠️ 注意
模型确实"记住"了一些事实（存在权重里），但它不是精准索引，而是统计+计算的产物。

四参数、参数量与显存占用

4.1 参数是什么

  • 神经网络的每一层里，有大量权重矩阵，矩阵里的每个数字就是一个参数。
  • 参数在训练中不断被微调，最终"拧"到一组能很好预测下一个词的值。

4.2 参数量级

规模总参数典型
小1B ~ 10B端侧 / 轻量
中30B ~ 100B通用
大200B ~ 700B前沿开源
超大1T ~ 2T+顶级闭源 / MoE

4.3 参数量 → 显存占用

粗略公式：权重显存 ≈ 参数量 × 每个参数占的字节数

实际部署还要加上运行时开销、临时激活、KV Cache、量化元数据和框架缓冲区；训练还要额外存梯度、优化器状态和检查点。

精度每参数字节说明
FP324 B训练常用高精度
FP16 / BF162 B主流推理/训练
FP81 B新硬件支持
INT4 / FP40.5 B极限量化
参数量FP16FP8INT4
8B16 GB8 GB4 GB
70B140 GB70 GB35 GB
200B400 GB200 GB100 GB
552B~1.1 TB~552 GB~276 GB
1T~2 TB~1 TB~500 GB

结论：前沿模型的权重是 TB 级显存，单卡装不下 → 必须切分到几十上百张卡。

4.4 MoE：又大又省的关键

  • MoE（混合专家）：总参数很大，但每次只激活一小部分。
  • 例：DeepSeek V4.1 Flash 约 552B 总参数 / 8B 激活。
  • 好处：模型容量大（强），单次计算量小（快、省）。

五训练 vs 推理

维度训练（Training）推理（Inference）
目的学用
计算前向 + 反向只前向
数据海量，多轮单条 / 批量
参数不断被调整固定不变
精度高（FP32/BF16）可低（INT8/FP4）
显存权重+梯度+优化器状态，3~4 倍权重 + KV Cache + 激活
成本一次性巨额长期随用户增长
硬件侧重大集群 + 高速互联低延迟 / 高吞吐 / 省电
💡 两个记忆点
  • 训练是入场费，推理是终身成本。
  • 训练要"前向 + 反向"两遍，推理只要"前向"一遍。

5.1 为什么推理能用低精度、训练不行

  • 训练容错低：要用误差反复微调上万亿参数，低精度误差累积会让模型"学废"。
  • 推理容错高：在可接受的质量损失范围内，可以压成 INT8/FP4，更省显存、更快；并不是所有模型和任务都能"几乎不变"。

5.2 推理为什么常受内存墙影响

  • 自回归解码阶段需要反复读取权重；对稠密模型，可以近似理解为每生成一个 token 都要遍历大部分权重。
  • MoE、批处理、权重驻留、缓存和算子融合会改变实际流量，因此"每个 token 完整重读全部权重"只是帮助理解的近似。
  • 计算本身很快，但显存带宽有限，读不完就得等；低批量解码尤其容易受带宽和访存影响。

5.3 KV Cache

  • 推理时要把上下文（你前面说过的话）缓存下来，叫 KV Cache。
  • 它随对话变长而增长，每个并发用户各占一份 → 用户越多，显存越挤。

六训练是如何"定出"参数的

核心：不是人设，是算法自动"试错微调"。

6.1 五步循环

1. 随机初始化参数（像乱拧的几万亿个旋钮）
2. 前向：喂一句数据 → 模型输出它的预测
3. 算损失：预测 vs 正确答案 → 一个"误差"数字
4. 反向传播：算每个参数对误差的"责任"（梯度 = 该往哪拧、拧多少）
5. 更新：每个参数朝"减小误差"的方向微调一丁点
   → 换下一条数据，重复 2~5（亿万次）

6.2 关键概念

  • 损失函数（Loss）：衡量"预测离正确答案有多远"。
  • 梯度（Gradient）：损失对每个参数的变化方向。
  • 反向传播（Backpropagation）：用链式法则把误差"分摊"到每个参数。
  • 梯度下降（Gradient Descent）：沿梯度反方向小步移动。
  • 学习率（Learning Rate）：步子大小。太大震荡，太小太慢。
  • 优化器（Optimizer）：Adam / AdamW / Muon 等，自动调整步长。演进的优化器能更快收敛。

6.3 与 PID 闭环控制的类比（很贴切）

控制论（PID）训练
目标 − 实际 = 误差预测 − 正确答案 = 损失
误差决定怎么调梯度决定方向
P 增益学习率
D 阻尼动量（Momentum）
自适应调节Adam 优化器

差异：这里是几万亿个旋钮同时闭环，而且"山"不止一个谷底、高度非线性。

6.4 "在浓雾里下山"类比

🌫 类比
你在浓雾的山上找谷底（误差最小点）：摸脚下坡度（梯度），往低处迈一小步，重复亿万次，最终滚到谷底。

6.5 换更强算法能减少算力依赖吗

  • 能，但有限：
    • ✅ 更好的优化器（SGD→Adam→Muon）确实迭代更少、收敛更快。
    • ❌ 但一般只带来 1.5~3 倍提升，不是 100 倍。
    • 且缩放定律：模型越大，反而要更多数据和算力。
  • 结论：算法效率是一个真杠杆，但替代不了"堆规模"。

6.6 为什么训练也用 GPU

  • 和推理一样是海量矩阵运算，但训练要前向 + 反向都算。
  • 还要额外存梯度 + 优化器状态（比推理多吃 3~4 倍显存）。

七显存与存储层级

7.1 为什么模型必须放显存

  • 推理阶段需要高频读取权重，通常需要高带宽显存。
  • NVMe SSD 常见为数 GB/s；DDR5 系统内存带宽通常为几十到数百 GB/s；高端 HBM 显存可达到数 TB/s。它们不是同一测量口径，不能简单相除。
  • 如果模型放到系统内存或 SSD，技术上可以运行，但通常会受到 PCIe、内存带宽、延迟和数据搬运影响，速度明显下降。
⚠️ 修正
推理技术上可以放内存甚至硬盘（消费级 llama.cpp 的 offload），只是慢很多；训练几乎必须全放显存。

7.2 存储层级全景

类型颗粒原理速度断电成本/容量
硬盘 HDD磁盘磁性、机械最慢保留最便宜/大
固态 SSDNAND 闪存电子存储，按块擦写快(GB/s)保留便宜/大
内存/显存DRAM电容存电荷，随机访问，需刷新很快丢失中/中
显存(高端)HBMDRAM 3D 堆叠，和 GPU 封装直连极快(TB/s)丢失贵/小
缓存SRAM触发器最快丢失最贵/最小
  • 为什么 DRAM 比 NAND 快：DRAM 能随机访问单元；NAND 要整块擦除，慢得多。
  • 为什么 HBM 的总带宽通常比 DDR5 高：位宽更宽、3D 堆叠/先进封装、靠近或直接连接 GPU 内存控制器。但"显存不走 PCIe"不等于所有 GPU 访问都完全不经过系统总线，具体取决于架构和数据路径。

7.3 为什么不用 SRAM 当显存

SRAMDRAM(HBM)
每 bit 晶体管~6 个1 管 + 1 电容
密度低（面积大）高
每字节成本贵 10~100 倍低
容量几十 MB80~288 GB
  • 密度是硬墙：SRAM 太占面积，装不下大模型。
  • 类比：SRAM = 手边小桌（快、小）；DRAM = 大仓库（慢点、能堆满）。
  • 例外：Cerebras 用整片晶圆做 SRAM 主存（~44GB），代价是天价。

7.4 量化

  • 把 FP16 权重压成 INT8/FP4，显存和计算量大幅下降，质量几乎不变。
  • 这是降推理成本的核心手段之一。

7.5 DRAM 容量上限

  • 截至本文日期，部分高端 AI 加速器的显存容量已达到约 192~288GB；具体取决于产品、HBM 代际和堆叠配置。
  • HBM4、更多堆叠层数和 3D DRAM 可能继续提高容量，但路线图和实际产品要以厂商发布为准。
  • 物理墙：DRAM 电容缩小会带来漏电、刷新和良率问题；3D DRAM 是重要方向，但不是已经兑现的统一标准。
  • 容量不是模型上限，因为可以多卡拼。

八为什么训练要几万张卡

两个原因，缺一不可：

原因 1：单卡装不下

  • 训练需同时存 权重 + 梯度 + 优化器状态（Adam 额外 2~3 份）。
  • 1T 模型 FP16 光权重就约 2TB；训练时再加梯度、优化器状态和激活，可能达到数 TB 甚至更高。
  • 单卡 150GB → 必须把模型切开分到多卡（模型并行）。

原因 2：为了快

  • 切数据、多卡同时算（数据并行），加快"亿万次循环"。

通信是扩展瓶颈

  • 每训练一步，几万张卡的梯度要互相同步、汇总。
  • 机内 NVLink 和跨节点网络的带宽、延迟通常都低于卡内 HBM；具体数值取决于代际、链路数量和网络拓扑，不能用单一数字代表所有集群。
  • 卡越多，通信占比越高 → 加速比不线性、效率下降。
装不下 → 被迫切分；切分 → 产生通信；通信 → 限制扩展。

十一句话总纲

大模型是一个参数极多（百 B~T 级）、占显存极大（数百 GB~数 TB）的"超级函数"：参数是"规律"不是"答案库"，所以不能查表、只能现算；现算就是海量简单矩阵运算，正好用 GPU 多核并行跑。训练是把这些参数"拧"好（费时又费显存），推理是拿拧好的参数"现算"答案（费带宽）。
