一项目起点与整体目标

本工程从 000_foc_analog（STM32F103）移植而来，最初是纯软件的 FOC 坐标变换仿真（无电机、无硬件），逐步演进为：

数学仿真 → SPWM 输出 → 霍尔测角 → 霍尔闭环电压控制 FOC

最终形态：用 3 路霍尔传感器测电角度，速度环输出"带符号电压指令"（q_ref），磁场角锁定转子（hall + theta_offset + 固定超前角），实现转速闭环控制、可正反转、可停车。

移植内容

  • foc_port（坐标变换数学库）：FOC_Clarke / Foc_Park / FOC_Rev_Park / FOC_Rev_Clarke
  • foc_debug（调试/仿真波形生成）
  • 新增：foc_pwm（SPWM 输出）、foc_hall（霍尔测角）、foc_ctrl（控制调度）

二硬件平台与引脚

主控

STM32G431RBT6（170MHz，APB1 = APB2 = 170MHz）

电机

CHB-BLDC4260，三相无刷内置霍尔（无驱动器）

  • 结构：定子 6 槽 / 转子 8 极 ⇒ 极对数 = 4
  • 额定：12V / 0.52A / 1600rpm，空载 2000rpm，最大 1.1A / 3.9W

驱动板

12V 三相无刷驱动板，3 路 PWM 输入（内含死区）

定时器分配

定时器用途配置 / 引脚
TIM620kHz 控制中断Prescaler=0, Period=8499
TIM4PWM 输出（U/V 相）CH1=PA11(UI), CH2=PA12(V)
TIM15PWM 输出（W 相）CH1=PB14(W)，带 Break/死区的高级定时器
TIM2霍尔接口CH1=PA5, CH2=PA1, CH3=PA2，CNT 每次霍尔跳变自动清零

霍尔引脚定义

PA1 = H1(bit0)　PA2 = H2(bit1)　PA5 = H3(bit2)，内部上拉

三阶段一：坐标变换数学仿真

纯数学，验证坐标变换正确性。所有变换为等幅值变换。

foc_port.h 关键定义

#define _PI        3.1415926535f
#define _PI_3      (_PI / 3.0f)
#define SQRT_3     1.73205080757f
#define LIMIT_ANGLE(x) fmodf(x, 2.0f*_PI)

四个变换函数（公式）

变换公式
Clarkeα = a,　β = (a + 2b) / √3
Parkq = cosθ·β − sinθ·α,　d = cosθ·α + sinθ·β
逆 Parkα = cosθ·d − sinθ·q,　β = cosθ·q + sinθ·d
逆 Clarkea = α,　b = (√3·β − α) / 2,　c = (−α − √3·β) / 2

foc_debug 两种自测模式

通过 TIM6 中断回调切换：

  1. 正逆闭环自检（Clarke_Park_Debug + RePark_ReClarke_Debug）：生成互差 120° 三相正弦 → Clarke → Park（d≈1, q≈0 自检）→ 逆变换还原。
  2. 反向输出（Rev_Output_Debug）：可调 d_ref / q_ref 经逆 Park + 逆 Clarke 生成三相正弦。

调试输出：Send_Debug_Data() 打包 CSV 经 USART 发 VOFA+ 画波形。

💡 关键经验
  • 模拟电角度 x 用 fmodf 取模到 [0, 2π)，形成锯齿（0→6.28→0），这是电角度周期的标准表示，跳回 0 是正常的。
  • 扇区内插值角度一定"上升"（sector×60 + frac×60），与方向无关。

四阶段二：SPWM 三相输出

foc_pwm.c：FOC_RUN_SPWM 把 dq 电压变成三路 20kHz 占空比写到 CCR。

核心流程

dq → 逆 Park → 逆 Clarke → +half_power 抬升到 [0, power] → 映射 CCR → 写定时器

关键代码

void FOC_RUN_SPWM(dq_t U_qd, float angle_el)
{
    input  = FOC_Rev_Park(U_qd, angle_el);    // dq -> αβ
    output = FOC_Rev_Clarke(input);            // αβ -> abc
    output.a += half_power;  // 抬升偏置使占空比绕 50% 摆动
    output.b += half_power;
    output.c += half_power;
    ccr = output / power * Tpwm;  // 映射 CCR，限幅 [0, Tpwm]
    A_H_SET_PWM(ccr);  B_H_SET_PWM(ccr);  C_H_SET_PWM(ccr);
}

参数：power = 12（母线电压），Tpwm = 8499（ARR）。

⚠️ 幅值限制
SPWM 线性区相电压峰值 ≤ power/2 = 6V，q_ref 超过会进入过调制。

遇到的问题与解决

1. HAL_TIMEx_MOEStart 编译报错 / 链接失败

  • 原因：G4 HAL 没有这个 API（那是 F1/F4 的老接口），G4 用的是 __HAL_TIM_MOE_ENABLE 宏。
  • 解决：直接删掉这行——HAL_TIM_PWM_Start() 内部已对带 Break 的 TIM15 自动执行 __HAL_TIM_MOE_ENABLE，PB14 会有输出。

2. 开环电机抖动不转

q_ref = 1V 太弱（扭矩不够克服齿槽力），调到 1.5~3V。

3. 冷启动抖动

9.55Hz 磁场瞬时给，转子咬不住 → 抖动。解决：加大 q_ref 或用软启动斜坡。

五阶段三：霍尔传感器测角

TIM2 霍尔接口：TI1/TI2/TI3 三路异或，计数器在每次霍尔跳变自动清零（SMS=RESET），所以 CNT = 本 60° 扇区内走过的 170MHz 计数，天然适合扇区内插值。

FOC_HALL_Update 核心逻辑（20kHz 每拍调用）

  1. 读 3 路霍尔合成码：code = H1 | H2<<1 | H3<<2
  2. 软件去抖：码需连续稳定 3 拍（150μs）才认可
  3. 查 sector_tab 得到扇区号 0~5
  4. 扇区跳变时：判断正/反转方向（hall_rev）、扇区周期低通、算带符号转速
  5. 方向感知插值：
    • 正转：hall = sector×60 + frac×60（低端升到高端）
    • 反转：hall = (sector+1)×60 − frac×60（高端降到低端）

扇区表（按电机实际转向标定）

static const uint8_t sector_tab[8] = {
    0xFF, 0, 4, 5, 2, 1, 3, 0xFF
    /* 000/111 无效；001->0, 010->4, 011->5, 100->2, 101->1, 110->3 */
};
/* 码序：电机正转 1->5->4->6->2->3，映射扇区 0->1->2->3->4->5 */

实测转速（带方向）

measured_rpm = ±4.25e8 / sector_period

（170MHz × 60 / (6 × 4 × sector_period)）

sector_period = 0.7×old + 0.3×new（低通滤波，速度估计更稳）

遇到的问题与解决（霍尔这块最曲折）

1. 霍尔码含毛刺（PWM 噪声耦合）

  • 现象：手转干净，电机一转就乱。
  • 解决：软件去抖（连续 3 拍同码才认）。

2. 扇区边界"卡死 + 突跳"

  • 原因：扇区实际比估计的慢，frac 提前顶到 1 → 干等在边界。
  • 解决：扇区周期低通滤波 + frac>1 时用实时 CNT 重新锚定。

3. 标定扇区表必须看原始码

  • 原因：raw 是物理事实，扇区号是我们贴的标签，顺序未知。
  • 方法：手转慢，记 raw 序列；校验"相邻码只差 1 位"（格雷码），毛刺序列不能用来建表。
  • 本电机实测干净序列：1→3→2→6→4→5（手转），电机转反向即 1→5→4→6→2→3。

4. 方向感知：反转时角度畸变

  • 现象：升一段、掉一截。
  • 原因：插值恒为 sector×60 + frac×60（只上升），反转时应从高端降到低端。
  • 解决：加 hall_rev 方向标志，反转用 (sector+1)×60 − frac×60。
  • 副作用收益：measured_rpm 同时带上正负号，闭环才能分正反转。

六阶段四：闭环速度控制

控制调度 FOC_CTRL_Step（TIM6 20kHz 每拍）

FOC_HALL_Update()
if (hall_calib_flag)   Ctrl_Calib_Step();    // 标定
else if (closed_loop)   Ctrl_Closed_Step();   // 闭环
else                    Ctrl_Speed_Step();    // 开环
FOC_RUN_SPWM((d_ref, q_ref), x)
Ctrl_Send_Step();                               // 每 50 拍置串口发送标志

开环 Ctrl_Speed_Step

angle_step = motor_rpm × POLE_PAIRS × 2π / (60 × 20000)

固定速率斜坡（RPM_ACCEL = 800rpm/s）→ x 累加。开环 = 磁场自由转，转子跟不跟得上看运气（会失步/抖）。

标定 Ctrl_Calib_Step（相位对齐）

x 冻结，强磁场（q_ref = 5~6V）拉转子 → 等稳定（50ms 角度 < 1°）→ theta_offset = x(度) − hall_angle_deg，归一化到 [0, 360)。

闭环 Ctrl_Closed_Step（最终方案，电压控制）

  1. motor_rpm == 0 时清积分 + 电压（停车释放）
  2. rpm_ref 斜坡（800rpm/s）
  3. 速度 PI → pid_v（带符号电压，限幅 ±6V）：
    • pid_err = rpm_ref − measured_rpm
    • i_term += pid_ki × pid_err（限幅 ±4V）
    • pid_v = pid_kp × pid_err + i_term（限幅 ±6V）
  4. q_ref = pid_v　// 带符号！正=正转，负=反转
  5. pid_delta = pid_delta_fwd（固定 30° 超前角）
  6. 磁场角 x = (hall + theta_offset + pid_delta) × π/180

闭环核心代码

static void Ctrl_Closed_Step(void)
{
    static float i_term = 0.0f;
    if (motor_rpm == 0.0f) { i_term = 0.0f; pid_v = 0.0f; }  // 停车释放
    { rpm_ref 斜坡 }
    pid_err = rpm_ref - measured_rpm;
    i_term += pid_ki * pid_err;          // 限幅 ±pid_i_max
    pid_v = pid_kp * pid_err + i_term;   // 限幅 ±pid_v_max
    q_ref = pid_v;                        // 带符号电压
    pid_delta = pid_delta_fwd;            // 固定超前角 30°
    x = (hall_angle_deg + theta_offset + pid_delta) * _PI / 180.0f;
    x = LIMIT_ANGLE(x);
    motor_rpm_actual = rpm_ref;
}

核心物理：为什么用"电压控制"而不是"δ 控制"

转速 ∝ V · cos(δ) / λm
  • V = q_ref（电压幅值），δ = 磁场超前角
  • δ 被限幅在 ±60° 内时，cos(δ) ∈ [0.5, 1]，转速只能在 2:1 范围调
  • 要停（转速→0）需要 cos(δ)→0 即 δ→±90°，但 90° 是零稳定裕量点
  • 结论：靠 δ 调速范围窄且停不下来，真正杠杆是电压 V

因此：速度环输出"电压 pid_v"，q_ref = pid_v（带符号），δ 固定 30°。

方向问题：为什么用 q_ref 正负反转

扭矩 ∝ V · cos(δ) − 反电动势

cos 是偶函数 → ±δ 扭矩方向相同，翻转 δ 无法反转。要反转必须把磁场整体翻转 180°：U_qd = (0, q)，q 变负 → 逆 Park 后磁场矢量翻转 180° → 扭矩反向。

七遇到的重要问题与解决方法

每个问题按：现象 → 原因 → 排查 → 解决 → 教训 展开。

编译 / 链接类
1HAL_TIMEx_MOEStart 编译报"声明隐式" + 链接报 Undefined symbol
现象：调用 HAL_TIMEx_MOEStart(&htim15)，编译警告 "declared implicitly"，链接报 "Undefined symbol"。
原因：这是 F1/F4 时代的老 API，STM32G4 的 HAL 里没有这个函数。G4 用宏 __HAL_TIM_MOE_ENABLE(htim) 直接置 BDTR.MOE 位。
排查：搜索 G4 HAL 头文件确认没有；同时发现 HAL_TIM_PWM_Start 对带 Break 的定时器会自动执行 __HAL_TIM_MOE_ENABLE。
解决：直接删掉 HAL_TIMEx_MOEStart(&htim15) 这一行，无需额外处理。
教训：跨芯片系列移植时，HAL API 名可能变化；报"声明隐式"先搜头文件确认。
2串口波特率上限：4M 不行、2M 波形坏、1152000 正常
现象：USART1 设 4M 收不到/乱码；设 2M 能收到但波形有毛刺丢帧；设 1152000 稳定。
原因：板载 GD32 做 DAPLink 的虚拟串口（CDC）是瓶颈：固件波特率表通常只支持到 ~2M；GD32 侧 UART 搬运 + USB CDC 端点调度在 2M 上丢字节；USB FS 带宽跟不上。STM32 硬件本身能跑 10.6M，但被 DAPLink 卡死。
解决：用 1152000（或更保守 921600）。2.5ms 一帧、每帧 ~20 字节，1152000 下只占 ~6% 带宽。
教训：板载 USB 转串口的波特率上限在桥接芯片/固件，不是 MCU。
3Keil Logic Analyzer 报 error 129 "Trace not supported"
现象：把变量加到 Logic Analyzer，报 "*** error 129: Trace not supported!"。
原因：Logic Analyzer 实时采样依赖 trace（ETM/ITM），而 DAPLink（CMSIS-DAP 实现）不支持 trace，是硬件能力限制。
解决：改用 Watch 窗口（暂停看全局变量）+ 串口发 VOFA+ 实时看波形。
教训：低成本 DAPLink/ST-Link 没有 trace，实时数据走串口上位机是通用方案。
控制行为类
4开环电机抖动不转（空载）
现象：q_ref=1、9.55Hz 电频率，电机只在原地抖，不转。
原因：q_ref=1V 只有 8% 占空比摆幅，扭矩太小，克服不了齿槽力和摩擦；冷启动直接给 9.55Hz 旋转磁场，转子从静止要瞬间同步，咬不住。
排查：q_ref 加到 1.5 能转，2.0 手捏有明显阻力 → 电压=扭矩。
解决：q_ref 提到 1.5~3V；之后加软启动斜坡。
教训：开环 SPWM 下"电压=扭矩=能否启动"，先保证扭矩再谈转速。
5软启动斜坡 bug："减速到越小越慢，目标设 0 完全不减"
现象：motor_rpm 从 100 改 0，电机很久都不减速；改小值时越减越慢。
原因：斜坡速率写成了与目标成正比：slew = fabsf(angle_step) * 0.00005f。目标 0 → angle_step=0 → slew=0 → 斜坡完全不动。
解决：改成固定速率斜坡（约 800rpm/s），与目标大小无关。
教训：加减速斜坡要用固定斜率，不能用"目标的比例"。
6纯 P（I=0）电机转一会就停
现象：pid_ki=0、kp=0.01、motor_rpm=100，电机转一小段就停。
原因：维持 100rpm 需要稳态电压 ≈ 1.5V；P 项最大输出 = 0.01×100 = 1V < 1.5V，电压永远不够。
解决：调完 P 的响应特性后必须把 I 加回来（ki=0.000002、i_max=4），I 负责"攒"出维持转速的稳态电压。
教训：电压源直驱方案下 I 是必需品不是可选项；纯 P 只用于观察响应，不能维持转速。
7停车后"自己动几下"（停 240° 后反向滑到 60°）
现象：motor_rpm 从 500 改 0，停稳后又自己反向一扇区一扇区地滑到 60° 才停。
原因：减速过程中 i_term 积成负值（在"刹车"）；停车后 pid_v = i_term（还是负的）→ q_ref 为负 → 磁场翻转 → 反向扭矩 → 被残留积分推着反向滑。
解决：在 Ctrl_Closed_Step 开头加：if (motor_rpm == 0.0f) { i_term = 0.0f; pid_v = 0.0f; }
教训：刹车会把积分积到"反方向"，停车/换向时积分残留是"自己动"的元凶，要主动清零。
霍尔 / 测角类
8霍尔码含毛刺（电机一转就乱，手转干净）
现象：手转电机霍尔角度干净；一上电驱动就乱跳。
原因：20kHz PWM 开关噪声耦合进 3.3V 霍尔信号线，扇区边界码被打成无效组合（000/111），角度冻结/乱跳。
解决：软件去抖——码需连续稳定 3 拍（150μs）才认可。
教训：PWM 驱动对霍尔引线是强干扰源；先软件去抖（成本最低），还不行再上 RC 滤波/屏蔽。
9扇区边界"卡死 + 突跳"（60/120/180/240 处平台）
现象：霍尔角度在扇区边界卡住好几个点，然后突跳到别的扇区。
原因：frac = cnt/sector_period，若本扇区实际比估计慢，frac 提前顶到 1.0，角度干等在边界。
解决：扇区周期低通（0.7 old + 0.3 new）；frac>1 时用实时 CNT 重新锚定。
教训：插值"线性假设 + 周期估计"，转速波动时会在扇区末端饱和，周期滤波 + 实时校正能显著压平。
10反转时角度畸变（升一段、掉一截，不是平滑递减）
现象：开环反转，霍尔波形是"每扇区上升、到边界掉一截"。
原因：插值恒为 sector×60 + frac×60（只上升）；反转时转子从扇区高端走向低端，正确应从高端降到低端。
解决：加方向标志 hall_rev，反转用 hall = (sector+1)×60 − frac×60。
教训：插值必须"方向感知"，否则反转波形畸形，且转速测不出方向。副作用：measured_rpm 带正负号。
11标定扇区表必须看原始码 + 格雷码校验
现象：按 raw 序列 0→2→1→5→3→4 建表，电机"直接不转"，角度仍乱。
原因：真实霍尔序列相邻码只差 1 位（格雷码）。序列 0,2,1,5,3,4 里 0(000) 是假码，且多处相邻跳变差 2 位，整条序列违反格雷码 → 含毛刺，不能建表。
解决：慢转手记 raw，取干净序列 1→3→2→6→4→5（相邻全差 1 位）；电机转向用 1→5→4→6→2→3 映射扇区 0~5。
教训：建表前必须用"格雷码只差1位"校验读数干净；000/111 是无效态。
闭环 / 方向类
12闭环反向跑飞（measured_rpm 恒负、pid_v 顶满 6V）
现象：闭环一开，电机反向满速跑，measured_rpm 显示负值，pid_v 饱和。
原因（两个叠加）：
  • 早期 measured_rpm 只有大小没有方向，反向后环路正反馈自激。
  • theta_offset 偏了约 180°，±30° 都落在"反向扭矩区"。
解决：方向感知后 measured_rpm 带 ± 号；theta_offset += 180 把有效扭矩角搬回正向区。
教训：测速必须带方向；方向错误会形成正反馈，环路越调越跑飞，是闭环最危险的失败模式。
13设 +100 和 -100 都是负满速跑飞 → cos(δ) 偶函数
现象：motor_rpm 无论设 +100 还是 -100，measured 都显示 -1000 满速。
根本原因：扭矩 ∝ V·cos(δ) − 反电动势，cos 是偶函数，±30° 的 cos 值相同 → ±δ 产生相同方向扭矩，翻转 δ 无法反转。
解决：要反转必须把磁场整体翻转 180°：q 变负 → 逆 Park 后磁场矢量翻转 180° → 扭矩反向。所以 q_ref = pid_v（带符号）。
教训：方向控制靠电压/电流符号（磁场翻转 180°），不是靠相位角 δ 的符号（cos 对称）。
14为什么扭矩角限幅不设 90°
原因：扭矩 ∝ sin(δ)，90° 是最大扭矩点，但 dT/dδ = cos(90°) = 0，即"零稳定裕量"——负载稍微一加，扭矩不增反降，直接失步。
结论：90° 是悬崖不是工作点；60° 已能出 sin60 = 0.87（87%）扭矩还留了裕量。
教训：工程上限留裕量，靠近理论极限 = 靠近不稳定。
15"90° 理想角"到底是哪个角（电流角 vs 电压角）
现象：把 pid_delta 设 90°，力气变小、pid_v 反而变大；设 5° 却力气很大。
原理：90° 理想指的是电流在 q 轴上（id=0 FOC），那是电流环才能强制做到的。我们是电压源直驱，控制的是电压角 δ：V_q = V·cos(δ) 才是 q 轴驱动电压 → δ 越小 V_q 越大 → 越出力。δ=90° 时 V_q=0 → 反而制动。
解决：电压源下 δ 固定 30°；要 90° 电流角必须上电流环。
教训：别把"电流角 90°"直接套到"电压角"上，两者物理完全不同。
调试 / 流程类
16中断里阻塞串口会卡死 20kHz 主环
现象：Send_Debug_Data 直接在 TIM6 中断里 HAL_UART_Transmit（阻塞），20kHz 中断被串口拖死。
解决：中断里只算好数据、置 uart_tx_flag；主循环 while 检测标志、再阻塞发送。
教训：中断里绝不能做阻塞 IO。
17电机跑飞长时间满载，电机烫手
现象：闭环跑飞时电机持续满载空转，摸起来很烫。
原因：pid_v 顶满 6V、正反馈一直加 → 长时间大电流。
处理：立即断电；驱动板余量大，但小电机（270g）容易退磁/烧绕组。
教训：调试前加堵转/超时保护；每次测闭环只跑几秒、摸温度，跑飞立刻断电。
18相位对齐标定 q_ref 要足（5~6V），否则 offset 不稳定
现象：q=1.5 标定时 theta_offset 每次不一样（120/165 等）。
原因：q=1.5 的磁场力远小于齿槽力，转子停在齿槽定位点而非磁场对齐位，每次起始位置不同 → offset 不同。
排查：q=6 后标三次全一致 → 确认弱磁场标定不可靠。
解决：标定时 q_ref 给 5~6V，磁场力 >> 齿槽力，转子每次被吸到唯一对齐位。
教训：校准必须在"被测信号能主导系统"的条件下做；弱激励 = 结果漂移。

九调试工具与技巧

  • VOFA+ 串口画波形：两列 = 实测霍尔角度 / 磁场角，正转两条同向上升锯齿。
  • 判断正反转的铁律：看 hall 扇区序号增减（递增=正转，递减=反转）；扇区内上升是插值，与方向无关。
  • 相位差(sim-hall) = theta_offset + pid_delta = 固定偏移 + 扭矩角，带负载会变大（越接近 90° 越接近最大扭矩），是负载指示器。
  • 标定 theta_offset：q_ref 给足、等转子停稳，用 hall_calib_flag 触发自动计算。
  • 测速方向验证：开环 forward 时 measured 应为正，闭环负说明方向/符号有问题。
  • Keil 无 trace：用 Watch 暂停看全局变量；实时波形走串口 VOFA+。
