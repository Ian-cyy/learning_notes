01强化学习概念与 PPO（直觉版）

这一篇把 RL 的“话”讲清楚，够读懂后面的 Go2 实战。原理直觉为主，少公式。

1. 三个词的关系

机器学习(ML)
 ├─ 监督学习：给 (输入,标签)，学映射
 ├─ 无监督学习：只给数据，找结构
 └─ 强化学习(RL)：给奖励，在交互中试错学“怎么做”
深度学习(DL) 是“模型结构”维度（神经网络），可以和上面三种交叉。

一句话：RL = 通过和环境交互、按奖励试错，学一个策略。

2. 核心概念（对照机器狗）

概念 英文 机器狗里是什么
智能体 Agent 策略网络（控制关节）
环境 Environment MuJoCo 物理世界
观测 Observation IMU、关节角、速度、指令（本体感知）
动作 Action 关节目标/力矩增量
奖励 Reward 走得快、站得稳、别摔的加权和
策略 Policy π(a|s) 给定观测输出动作的神经网络
价值 Value V(s) 当前状态未来能拿多少奖励（评论家估计）
优势 Advantage A “这个动作比平均好多少”，PPO 用
回合 Episode 从 reset 到摔倒/超时
折扣 γ 未来奖励打折

3. MDP

环境被建模为马尔可夫决策过程 (S, A, P, R, γ)。RL 的目标：找到策略 π 使期望累计折扣奖励最大。 - on-policy（PPO 属于）：用当前策略采的数据更新，稳定但样本效率一般。 - off-policy（SAC/DDPG）：用经验池，样本效率高，但调参更敏感。

4. PPO 直觉（本项目用的算法）

  • 演员-评论家（Actor-Critic）：Actor 出动作，Critic 估价值。
  • 近端：限制每次更新时策略变化不能太大（clip 比率 r_t = π_new/π_old 到 [1-ε, 1+ε]），避免“一步走崩”。
  • 优势估计用 GAE（广义优势估计），平衡偏差/方差。
  • 行为：稳定的深度 RL 基线，不需要太精细调参就能训出不错策略。

关键超参（train_jax_ppo.py / locomotion_params.py）：学习率、num_envs、num_timesteps、discounting、entropy_cost、mini-batch 数等。

5. 奖励设计（reward shaping）

奖励决定“学成什么样”，比算法更重要： - 跟踪类（正）：速度跟踪 exp(-(v-v_cmd)²/σ)、姿态保持、抬脚高度。 - 惩罚类（负）：力矩、动作变化率、关节限位、终止（摔倒）。 - 陷阱 reward hacking：策略会找“刷分但不做事”的捷径。例：用“抬脚高度方差”做对称奖励 → 策略干脆都不抬脚（方差=0 拿满分）。设计要防“退化解”。 - 常用结构：reward = clip(Σ 权重×各项, 0, …)，每步再乘 dt。

6. 指标怎么读（TensorBoard）

指标 含义 / 健康信号
eval/episode_reward 总奖励，应上升后平台
eval/avg_episode_length 平均回合长度，满值=不摔
eval/episode_reward/<项> 各分项，定位是哪项在变
eval/episode_reward_std 方差，过大=不稳定
training/kl_mean 策略更新幅度，过大=崩
training/sps 每秒步数（吞吐）

重要：reward 高 ≠ 行为好（可能被刷分）。最终要逐脚/逐行为验证（见 03/04 篇）。

7. 该训多久 / 并行

  • num_timesteps 不是累计（每次运行从 0 数），续训靠 --load_checkpoint_path。
  • num_envs 越大采样越快，但吃显存（本项目 6G 上 2048 常用，OOM 降到 1024）。
  • 通常几千万步收敛；看 reward 平台 + 行为验证，而不是死等步数。

02Go2 环境与训练

用 mujoco_playground（DeepMind）+ Brax PPO 在 Go2 上做 locomotion。 代码：~/mujoco_ws/go2_rl/mjplay/

1. 工具栈

组件 作用
MuJoCo / MJX 物理引擎 / GPU 并行版
mujoco_playground 环境集合 + 训练脚手架（我们基于它写 Go2 env）
Brax JAX 的 RL 库（PPO）
JAX 自动微分 + JIT + GPU
TensorBoard 训练曲线

安装要点（版本强相关，见 05 篇）：mujoco_playground v0.1.0（支持 Py3.10）、mjx 3.15、jax 0.6.2；menagerie 的 unitree_go1/go2 放到 playground 期望的 external_deps 路径。

2. 环境（registry 里的名字）

环境 任务 说明
Go2JoystickFlatTerrain 行走（可指定 vx/vy/wz） 主 walk 环境
Go2Getup 倒地起身 obs 42，动作相对当前
Go2JumpFlatTerrain 跑/蹦 由 jump 演化
Go2StandJumpFlatTerrain 立定跳越墙 墙 0.15m，obs 48
MyDogStandFlatTerrain / MyDogWalkFlatTerrain 自建狗站立/行走 见 04 篇

目录：mjplay/mujoco_playground/_src/locomotion/go2/（joystick.py/getup.py/jump.py/stand_jump.py + xmls/）。

3. 训练命令

bashcd ~/mujoco_ws/go2_rl/mjplay
python3 -u learning/train_jax_ppo.py --env_name=Go2JoystickFlatTerrain \
  --num_timesteps=100000000 --num_envs=2048 --num_evals=10 \
  --domain_randomization=True --use_tb=True --num_videos=0 --suffix=myrun
  • --suffix 决定日志目录名：logs/<ENV>-<时间>-<suffix>/。
  • --domain_randomization=True：域随机化（摩擦/质量/质心等），利于 sim2real。
  • --num_videos=0：不录视频（省时）。
  • 续训：加 --load_checkpoint_path=logs/<run>/checkpoints（仅同族任务、obs/动作一致才行）。

4. 监控

bashcd ~/mujoco_ws/go2_rl/mjplay
tensorboard --logdir logs

看 eval/episode_reward 上升后平台、avg_episode_length 满值、分项是否健康（见 01 篇第 6 节）。

5. checkpoint 语义（易错）

  • 脚本里 num_timesteps 每次从 0 数；真正进度看 checkpoints/0000* 目录名的步数。
  • checkpoint 只在 eval 时保存；num_evals 太小会丢中间进度。
  • 导出/续训都用具体步数目录最稳（或传 checkpoints/ 让它取最新）。

6. 显存 / 吞吐

  • 6G（RTX 3060 Laptop）：num_envs=2048 常用；OOM 就 1024。
  • 首次运行含 JIT/XLA 编译（几分钟）正常；训练中 GPU 忽满忽停是编译/日志/存盘。
  • 训练（JAX）和使用/查看（ONNX）不要同时开，两个 JAX 进程会挤爆内存。

7. 观测/动作（walk）

  • obs 48 维（本体感知，无视觉 → 盲走），含指令；privileged 观测给 Critic（可选）。
  • 动作 = 相对默认姿态的关节增量（乘 action_scale），env 内做 PD 转力矩。

详见 mjplay/.../go2/joystick.py 与 03_Go2四任务 篇。

03Go2 四个任务：walk / getup / run / standjump

同一个 Go2 平台，做了 4 个技能。每个任务改动、结果、导出如下。

1. Walk（行走）Go2JoystickFlatTerrain

  • 目标：按指令 vx/vy/wz 走。
  • obs 48（本体感知，无视觉），动作=关节增量，env 内 PD。
  • 训练：~100M + DR，收敛后换多个种子；是主策略。
  • 导出：go2_policy.onnx。

2. Getup（倒地起身）Go2Getup

  • 移植自 go1 的 getup.py + scene_mjx_fullcollisions_flat_terrain.xml。
  • obs 42（无 linvel/command）；动作 = 当前关节角 + a×0.5（相对当前，非默认姿态）。
  • reward：orientation / torso_height / posture（站直且到位才给）/ stand_still；energy_termination=1e5 + 非有限值也终止。
  • reset：随机倒地；在地面附近放置（不自由落体撞击）+ settle 0.5s。
  • 关键修复（NaN 毒死训练）：朴素移植 + DR 会在 ~13M 变 NaN。修法：① obs/reward nan_to_num + clip；② reset 地面附近起步；③ 有限能量终止。
  • 结果：no-DR 100M，reward 0.1→~17.6（~46M 后平台），无 NaN、ep_len 恒 300。
  • 导出：go2_getup.onnx（no-DR）、go2_getup_dr.onnx（DR）。

3. Run（跑/蹦）Go2JumpFlatTerrain

  • 由 jump 任务演化，策略学成“跑/弹跳（bound）”式快速移动。
  • 导出：go2_run.onnx；查看 onnx_go2_run_viewer.py。

4. StandJump（立定跳越墙）Go2StandJumpFlatTerrain

  • 场景：scene_mjx_feetonly_wall_flat_terrain.xml，墙高 0.15m。
  • obs 48（加 forwardvector）；动作 12。
  • reward 设计（多版迭代）：cross（越墙）/stay（落地稳定）/fall_penalty/air_forward（空中前向）/air_height/heading。
  • 结果：v4 训到 ~69M，reward 峰值 ~11；导出 go2_stand_jump.onnx。

5. 多技能切换（运行时）

  • 一个时刻只跑一个策略；多个 ONNX 靠状态机调度。
  • 翻倒检测（IMU gravity 偏离 / 机身高度低）→ 切 getup；站起后切回 walk。
  • onnx_go2_switch_viewer.py 实测：推倒 → ~2.2s 自起 → 切回走路。
  • 注意：不同技能的 obs 维度/拼装、动作映射不同，各自用自己的那套。

6. 结果速览

任务 环境 obs 关键结果 ONNX
walk Go2JoystickFlatTerrain 48 稳定行走/抗扰 go2_policy.onnx
getup Go2Getup 42 reward→17.6，无 NaN go2_getup(_dr).onnx
run Go2JumpFlatTerrain 48 跑/弹跳 go2_run.onnx
standjump Go2StandJumpFlatTerrain 48 越 0.15m 墙，reward~11 go2_stand_jump.onnx

04ONNX 导出与部署

训练用 JAX，部署用 ONNX + onnxruntime（轻、跨平台、真机友好）。 脚本：~/mujoco_ws/go2_rl/scripts/export_go2_onnx.py

1. 思路：手搓 ONNX 图（不需要 TensorFlow）

策略是个 MLP：(obs − mean)/std → Dense-swish ×N → Dense → 取前 act 维 → tanh。 直接从 Brax checkpoint 里取权重，手搭 ONNX 计算图。

步骤（export_go2_onnx.py）： 1. ckpt_load(checkpoint) → normalizer, params；取 normalizer.mean/std["state"]、params["params"]["hidden_i"]["kernel"/"bias"]。 2. 用 onnx.helper 搭节点： - Sub(obs, mean) → Div(·, std) 归一化； - 每层 MatMul → Add；激活用 swish = x·sigmoid(x)（Sigmoid+Mul）； - 最后一层 Split 成 loc, scale，对 loc 取 Tanh 得动作。 3. 设 opset 11、ir_version 10（新版 IR 会导致 onnxruntime 报 “Unsupported IR version”）。 4. onnx.checker.check_model + 用 onnxruntime 和 JAX 推理数值比对（应 <1e-5）。

2. 导出命令

bashcd ~/mujoco_ws/go2_rl
sed 's/Go2JoystickFlatTerrain/<ENV>/' scripts/export_go2_onnx.py > /tmp/export.py
python3 /tmp/export.py --ckpt mjplay/logs/<run>/checkpoints --out policies/<name>.onnx
  • --ckpt 传 checkpoints/（自动取最新）或具体 0000* 目录。
  • 脚本会打印每层权重形状 + 最后的 max abs diff（应为 0 或 1e-6 量级）。

3. 轻量查看器（onnxruntime + 普通 MuJoCo，秒开）

bashpython3 scripts/onnx_go2_viewer.py --vx 0.6          # walk
python3 scripts/onnx_go2_getup_viewer.py --fallen    # getup
python3 scripts/onnx_go2_run_viewer.py               # run
python3 scripts/onnx_go2_standjump_viewer.py         # 立定跳
python3 scripts/onnx_go2_switch_viewer.py --vx 0.6   # walk↔getup 切换

查看器做的事： 1. mujoco.MjModel.from_xml_path 载入同一模型； 2. 每 ctrl_dt 组装观测（gyro / gravity / command / 关节角 / 速度 / last_act …）； 3. onnxruntime.InferenceSession 推理得动作； 4. env 内 PD：target = default + act*scale，tau = Kp(target−q) − Kd·qd，clamp； 5. mujoco.mj_step × n_substeps，viewer.sync()。

4. 部署注意

  • obs 维度和拼装必须和训练时一模一样（少一维/顺序错 = 策略失效）。
  • 动作映射（相对默认 or 相对当前）也要一致。
  • 真机：onnxruntime 在树莓派上 CPU 推理 1–5ms 级；用 CPUExecutionProvider。
  • 注意 MJX↔MuJoCo/真机的差距（见 04 篇自建狗结论）：训练环境里的好策略，不一定直接迁移。

5. 关键坑

坑 解
Unsupported IR version 14 make_model(..., ir_version=10)
导出的 ONNX 和训练不一致 检查 mean/std、层顺序、Swish 实现、Tanh、Split
维度对不上 用 env.observation_size["state"]、env.action_size 确认

4. 调参经验（少走弯路）

  • 先小规模验证：num_envs 小、num_timesteps 短，确认环境/reward 不炸再放大。
  • 一次只改一个东西：奖励项、权重、域随机化，分开看效果。
  • 看分项不看总分：eval/episode_reward/<项> 才知道是哪项在动。
  • reward hacking 自查：把所有“正奖励”去掉后，策略还会做该做的事吗？若不会，说明它在刷别的项。
  • 行为验证：训完一定逐动作/逐脚检查（姿态、抬脚、速度），不能只看 reward 数。
  • 续训判据：obs 维度 + 动作语义不变 → 可暖启动；变了 → 新 env + 新 ONNX。

5. 一句话

RL 里 90% 的坑是环境和奖励，不是算法。PPO 很稳，真出问题多半是观测拼错、奖励被刷、或 sim 与真机不一致。

06RL 术语 / 英文词速查（语境对照）

更新：2026-10-10 ｜ 配套：RL_学习笔记_从概念到Go2实战.md 按"我们聊天里怎么用"解释，不是字典定义。

A. RL 核心概念

词 中/含义 语境

environment (env) 环境 MuJoCo 仿真世界（含地形/物理）

step (timestep) 步 一次决策；ctrl_dt=0.02s→50Hz
