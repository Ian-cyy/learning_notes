01安装与最小仿真

MuJoCo 用起来就三样：一个模型 MjModel、一个状态 MjData、一个循环 mj_step。 本文给最小可跑例子，后面所有控制/RL 都建立在这套骨架之上。

1. 安装

bash## 基础（物理引擎 + python 绑定 + viewer）
pip install mujoco

## 本项目常用配套
pip install scipy osqp casadi          # 控制/优化
pip install onnx onnxruntime           # 导出/部署策略
## 强化学习见 03 篇（jax / brax / mujoco_playground）

版本要配套：jax、mujoco-mjx、mujoco_playground、onnx 之间版本强相关，装错会各种报错（见 03/05 踩坑）。

2. 最小仿真循环

pythonimport mujoco, mujoco.viewer

model = mujoco.MjModel.from_xml_path("scene.xml")   # 编译模型（只读，建一次）
data  = mujoco.MjData(model)                         # 运行时状态（每步变）

for _ in range(1000):
    data.ctrl[:] = 0.0                # 写控制量（执行器顺序 = data.ctrl 下标）
    mujoco.mj_step(model, data)       # 物理积分一步（dt = model.opt.timestep）
    # 读 data.qpos / data.qvel / data.xpos ...

3. 两种 Viewer

python## (a) 阻塞式：自带仿真循环
mujoco.viewer.launch(model, data)

## (b) 被动式：自己 step、自己 sync（推荐，可控）
with mujoco.viewer.launch_passive(model, data) as v:
    while v.is_running():
        mujoco.mj_step(model, data)
        v.sync()

被动 viewer 操作：左键旋转 / 右键平移 / 滚轮缩放 / Ctrl+右键施力（施力常用于“推倒测试”，见 go2/go2_push_test.py）。

4. 加载现成模型

  • 官方模型库：~/mujoco_ws/mujoco_menagerie（go2 / spot / anymal / g1 / t1 / cassie / panda… 73 个）。
  • 直接 from_xml_path(".../unitree_go2/scene.xml")。

5. 关键约定（新手必看）

  • 单位：米、kg、弧度、秒。
  • model 编译后不可改；data 每步变。
  • 一个 data 不能多线程共享；并行多个环境 = 建多个 MjData（或上 MJX）。
  • timestep 越小越准越慢；控制频率靠外层循环自己控制（不是 timestep）。
  • 关节顺序 = qpos/qvel/actuator 的定义顺序，改 XML 顺序会错位（RL 里尤其致命）。

6. 对照本项目

  • 经典控制骨架：cartpole/mpc_cartpole.py、go2/go2_stand.py
  • 自建狗：go2_rl/mjplay/mujoco_playground/_src/locomotion/mydog/xmls/mydog_simple.xml

02XML 结构与核心概念

MuJoCo 的模型是 MJCF（一种 XML）。理解 6 个标签：worldbody / body / joint / geom / actuator / sensor，加 keyframe，就能读懂大多数模型。

1. 整体骨架

xml<mujoco model="x">
  <compiler angle="radian" autolimits="true"/>
  <option timestep="0.002" integrator="Euler"/>
  <default>
    <geom rgba="0.6 0.6 0.6 1"/>
  </default>
  <asset>
    <mesh name="body" file="assets/body.stl"/>
  </asset>
  <worldbody>
    <light pos="0 0 2" dir="0 0 -1"/>
    <geom type="plane" size="5 5 0.1"/>          <!-- 地面 -->

    <body name="base" pos="0 0 0.4">
      <freejoint/>                                <!-- 6 自由度漂浮关节 -->
      <geom type="box" size="0.1 0.1 0.05"/>
      <body name="leg">                          <!-- 子 body 原点 = 父 body 坐标系 -->
        <joint type="hinge" axis="0 1 0" range="-1.5 1.5"/>
        <geom type="capsule" fromto="0 0 0 0 0 -0.3" size="0.02"/>
      </body>
    </body>
  </worldbody>

  <actuator>
    <motor name="m_hip" joint="leg_joint" gear="1" ctrlrange="-12 12"/>
  </actuator>

  <sensor>
    <gyro site="imu" name="gyro"/>
    <accelerometer site="imu" name="acc"/>
    <framexaxis objtype="site" objname="imu" name="forwardvector"/>
    <framezaxis objtype="site" objname="imu" name="upvector"/>
  </sensor>

  <keyframe>
    <key name="home" qpos="..." ctrl="..."/>
  </keyframe>
</mujoco>

2. 六个核心标签

标签 作用 要点
worldbody 世界 + 所有刚体树 地面 type="plane" 放这里
body 刚体；嵌套表示树 pos/quat 相对父 body；joint 写在 body 里
joint 自由度 freejoint(6DOF) / hinge(绕轴转) / slide(平移)
geom 碰撞+外观 type=box/sphere/capsule/cylinder/mesh/plane…
actuator 执行器 motor(力矩)/position/general；顺序 = data.ctrl 下标
sensor 传感器 gyro/accelerometer/frame*/contact…，读 data.sensordata

几何属性差别：size 对不同类型含义不同（box=半尺寸3个、sphere=半径1个、capsule=半径1个、mesh=缩放3个）。fromto 可直接给胶囊/圆柱两端点。

3. qpos 的自由度顺序（非常关键）

data.qpos 按关节定义顺序排列： - 每个 freejoint 占 7 个数：x y z qw qx qy qz（位置 + 四元数） - 每个 hinge/slide 占 1 个数（关节角/位移）

关系：

qpos = [free(7)] + [joint1, joint2, ...]
qvel = [free(6: 线速度3 + 角速度3)] + [joint1_dot, ...]

例（自建狗 mydog_simple.xml）：qpos = 7(free) + 8(4 腿×hip/knee) = 15 维；qvel = 6 + 8 = 14 维。 所以关节角是 data.qpos[7:]、关节速度是 data.qvel[6:]。偏一位就全错（RL 里 reward/obs 全崩）。

4. 执行器与 ctrl

  • data.ctrl 长度 = 执行器个数 model.nu，下标顺序 = actuator 定义顺序。
  • 每个执行器绑一个 joint（或 tendon/site）。<motor joint="..."> 是最常见的力矩源。
  • 与关节的对应可查：model.actuator_trnid[a,0] = 该执行器控制的关节 id。
  • 策略输出顺序 = 执行器顺序 = 关节顺序，三者要一致（导出 ONNX 时尤其注意）。

5. 碰撞：contype / conaffinity（位掩码，大坑）

  • 只有 (A.contype & B.conaffinity) != 0 或 (B.contype & A.conaffinity) != 0 时两 geom 才碰撞。
  • 设 contype=0, conaffinity=0 → 该 geom 只做外观、不参与碰撞（=视觉模型）。
  • density=0 → 不贡献质量。
  • 坑：2 & 1 == 0，如果腿的 contype=2、地面 conaffinity=1，则腿不碰地、直接穿地（本项目自建狗踩过，见 04 篇）。

6. default 与继承

xml<default>
  <geom group="1" type="mesh" density="0" contype="0" conaffinity="0"/>
  <default class="collision"><geom type="capsule" contype="1"/></default>
</default>
  • default 里的属性作为默认值，单个 geom 可覆盖。
  • 用 class="..." 分组；碰撞体常单独一个 class。

7. keyframe（初始/参考姿态）

xml<keyframe>
  <key name="home" qpos="0 0 0.30 1 0 0 0  -0.23 0.40 ..." ctrl="0 ..."/>
</keyframe>
  • 用 mujoco.mj_resetDataKeyframe(model, data, 0) 一键复位到该姿态。
  • 是“初始姿态 / 参考站姿”的标准做法（本项目 stand 的默认姿态就取它）。

8. 单位和角

  • compiler angle="radian" → 所有角度用弧度（本项目都用 radian）。
  • <option> 里 timestep、integrator、gravity、solver 等全局设置。

9. 常见坑速记

现象 原因
模型穿地/不掉落 contype/conaffinity 位掩码不匹配
关节不按预期转动 axis 方向/符号、或 qpos 顺序错位
打开模型是散的 body 的 pos/quat 相对父级写错
mesh 显示异常 网格局部坐标系/导出问题（见 04 篇镜像修复）

03状态读写与常用 API

记住两大数据结构：MjModel（静态模型，只读）与 MjData（动态状态，每步变）。 下面是实际会用到的高频字段与函数。

1. 状态读取（MjData 高频字段）

字段 含义
data.qpos 广义坐标（关节位置；free 关节含位置+四元数）
data.qvel 广义速度
data.qacc 广义加速度
data.ctrl 控制输入（执行器顺序）
data.xpos[i] 第 i 个 body 的世界位置
data.xquat[i] 第 i 个 body 的世界四元数
data.geom_xpos[i] / geom_xmat[i] geom 的世界位置/旋转矩阵（9 个，扁平）
data.site_xpos[i] / site_xmat[i] site 的世界位置/旋转
data.xanchor[j] 第 j 个关节的世界锚点
data.sensordata 传感器数据（按 sensor_adr 索引）
data.qfrc_actuator 执行器作用到关节的广义力
data.qfrc_bias 科氏/重力等偏置力

想按名字取对象 id：mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_JOINT, "hip_L1")； 反向：mujoco.mj_id2name(...)。上面的 model.joint("hip_L1").id 是更简洁的写法。

2. 常用函数

pythonmujoco.mj_forward(m, d)         # 只做正运动学/动力学（不积分）——读世界位姿前要调
mujoco.mj_step(m, d)            # 前进一个 timestep（积分）
mujoco.mj_resetData(m, d)       # 复位到 qpos0
mujoco.mj_resetDataKeyframe(m, d, 0)   # 复位到第 0 个 keyframe

## 名字 <-> id
jid = mujoco.mj_name2id(m, mujoco.mjtObj.mjOBJ_JOINT, "knee_L1")
## 关节 -> qpos/dof 地址
qadr = m.jnt_qposadr[jid]; vadr = m.jnt_dofadr[jid]

3. 雅可比（做控制/IK/MPC 常用）

pythonjacp = np.zeros((3, m.nv)); jacr = np.zeros((3, m.nv))
mujoco.mj_jac(m, d, jacp, jacr, point, body_id)   # 到某点的平动/转动雅可比
  • mj_jacBody / mj_jacGeom / mj_jacSite 也有封装。
  • 足端速度 = jacp @ qvel；关节力矩映射到足端力 = Jᵀ f。

4. 数值线性化（做 MPC 的神器）

pythonA = np.zeros((m.nv, m.nv)); B = np.zeros((m.nv, m.nu))
mujoco.mjd_transitionFD(m, d, 1e-6, True, A, B, None, None)   # 在 (x,u) 处数值求 ∂x'/∂x, ∂x'/∂u
  • 用于线性 QP-MPC：拿到 A/B 后在平衡点线性化（见 cartpole/mpc_cartpole_qp.py）。

5. 批量前向预测（采样 MPC）

pythonimport mujoco.rollout
states, _ = mujoco.rollout.rollout(model, datas, init_state, controls, persistent_pool=True)
  • init_state 形状 (N, nstate)，controls 形状 (N, H, nu)，C++ 多核并行“快进”。
  • 见 cartpole/mpc_cartpole.py 的采样 MPC。

6. 复位到某个姿态（手动设 qpos）

pythondata.qpos[:] = model.qpos0
for j in range(model.njnt):
    if model.jnt_type[j] == mujoco.mjtJoint.mjJNT_HINGE:
        data.qpos[model.jnt_qposadr[j]] = 0.0
mujoco.mj_forward(model, data)

7. 读传感器（例如陀螺/重力方向）

pythongyro = data.sensor("gyro").data                 # 3 维
## “重力方向”（世界系下，供策略用）：用 imu site 的旋转矩阵转[-z]
imu = model.site("imu").id
gravity = data.site_xmat[imu].reshape(3,3).T @ np.array([0,0,-1.0])

8. 常见坑

现象 原因
世界坐标不更新 改了 qpos 但没 mj_forward
索引全错 qpos 有 free 关节（占 7 个），忘记偏移 7
传感器读越界 用 model.sensor_adr[id]，多分量传感器还有 sensor_dim
姿态解算乱 geom_xmat/site_xmat 是长度 9 的扁平数组，要 .reshape(3,3)

04MJX 与 GPU 并行

普通 MuJoCo 跑在 CPU、单实例。要做大规模并行（几千个环境同时采样）→ 用 MJX（MuJoCo 的 JAX 版，跑在 GPU）。 强化学习（03 篇）就是建立在 MJX 之上的。

1. 三层生态

MuJoCo      纯 C 物理引擎（CPU），Python 绑定 mujoco
  └─ MJX    MuJoCo 的 JAX 重实现：put_model → 上 GPU，可 jit / vmap / scan
       └─ mujoco_playground   DeepMind 的“环境 + Brax PPO”集合（我们用的就是它）
            └─ Brax         JAX 的 RL 库（PPO 等）

2. 把模型搬到 JAX

pythonimport jax, jax.numpy as jp
from mujoco import mjx

mj_model = mujoco.MjModel.from_xml_path("scene.xml")
mx = mjx.put_model(mj_model)           # 把 MjModel 变成 JAX 可微分/可 jit 的 MJX 模型
dx = mjx.make_data(mx)                # 或 mjx.put_data(mj_model, mj_data)
dx = mjx.forward(mx, dx)              # JAX 版前向

## 一步仿真（在 jit 内）
@jax.jit
def step(mx, dx):
    dx = dx.replace(ctrl=...)
    return mjx.step(mx, dx)

要点： - mjx.put_model/put_data 之后，数据是 JAX 数组，能在 jit/vmap/scan 里跑、能上 GPU。 - MJX 支持有限但够用；复杂 equality/闭环在 MJX 可能不稳（见 04 篇自建狗，改用串联腿）。 - MJX 里的多环境 = 在数据上加一个 batch 维（用 vmap），一次前向算 N 个环境。

3. 并行 rollout（采样）

pythonstates = mjx.rollout(...)   # 或用 jax.lax.scan 自己写
  • 训练时常见：num_envs 个环境并行跑，一次收集一大批经验（见 03 篇训练）。

4. 和 mujoco_playground 的关系（本项目用法）

  • mujoco_playground 提供一套 mjx_env.Env 接口：reset(rng)、step(state, action)、observation_size、action_size。
  • 我们的环境（Go2JoystickFlatTerrain、MyDogWalkFlatTerrain…）都是继承它、用 MJX 定义 reset/step。
  • Brax 的 PPO 在这些环境上训练：train_jax_ppo.py。

5. 版本 / 坑

  • jax、mujoco-mjx、mujoco_playground 版本强相关，装错就报各种构造/字段错误。
  • 本项目固定：mujoco_playground v0.1.0（支持 Python 3.10）、mjx 3.15、jax 0.6.2。
  • MJX 早期用 nconmax，新版本改为 naconmax（踩过，见 03/05 篇）。
  • 编译很慢（JIT/XLA autotune）：首次 4–7 分钟正常；开编译缓存可秒过。

6. 什么时候用 MJX / 什么时候用普通 MuJoCo

场景 选择
少量实例、调试、看模型、经典控制 普通 MuJoCo（CPU）
大规模并行采样、强化学习训练 MJX（GPU）
部署/真机推理 都不需要——直接用 ONNX + onnxruntime
