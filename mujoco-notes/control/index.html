01CartPole：PID 与两种 MPC

最小可玩的控制实验台。用同一套 MuJoCo 倒立摆对比：PID vs 采样 MPC vs 线性 QP-MPC。 代码：~/mujoco_ws/cartpole/{mpc_cartpole.py, mpc_cartpole_qp.py}

1. 系统

  • 状态 x, θ, ẋ, θ̇（4 维）；控制 = 小车水平力 u ∈ [-30, 30] N。
  • dt = 0.01s；XML 内嵌在脚本里（CART_XML）。

2. PID（基线）

pythonu = K_ANG*θ + K_DTH*θ̇ + K_X*x + K_VX*ẋ      # 负反馈，clip 到 ±30

调参结论：K_ANG=180, K_DTH=10, K_X=4, K_VX=5（杆稳 + 车回中）。

3. 采样 MPC（mpc_cartpole.py）—— 最直白的 MPC

每步： 1. 读状态； 2. 随机撒 N_SAMPLES=400 组、每组 H=60 步的分段常数输入（REPEAT=5，一段保持 5 拍）； 3. mujoco.rollout.rollout(...) 并行“快进”60 步； 4. 代价打分：Σ W_ANG·θ² + W_X·x² + W_VX·ẋ² + W_DTH·θ̇² + W_U·u² + 终端代价； 5. argmin 取最优序列的第 1 步下发，下一拍重来。

核心代码：cartpole/mpc_cartpole.py 的 mpc_action()（:60-74）。 - 关键点：物理引擎当预测模型，不用建模、不用梯度；缺点是维数一高就撒不中。

4. 线性 QP-MPC（mpc_cartpole_qp.py）—— 真正的 MPC

思路：线性化 + 展开成二次规划（QP），用 OSQP 求精确最优。 1. 线性化：在平衡点数值求 A,B：mjd_transitionFD(m, d, 1e-6, True, A, B, ...)（:55）； 2. 展开：X = Sx·x0 + Su·U（Sx/Su 由 A,B 累乘，:58-63，只算一次）； 3. 二次型：代价 Σ xᵀQx + uᵀRu → ½ Uᵀ P U + qᵀU - Q_WEIGHT=[1,100,1,1](x,θ,ẋ,θ̇)，R=0.01，N_HORIZON=30 - P = 2(Suᵀ Q̄ Su + R̄)（启动算一次）、q = 2 Suᵀ Q̄ Sx·x（每步更新） 4. 约束 |u|≤Umax → osqp 求解，取 U[0]（:86-89）。

5. 抗扰实验结论（--compare，推小车 0.1s）

控制器 结果
PID / 线性 QP-MPC 都能稳到 ~50N（接近物理上限）
采样 MPC 明显更差

持续恒力（力一直存在，非冲量）： - PID / 采样 MPC 停在有限偏移（可接受）； - QP-MPC 会跑偏（因为它是围绕平衡点的线性模型 + 短视界开环预测）。

结论：冲量扰动下 QP-MPC 追平 PID；持续外力场景用 PID；采样 MPC 在本任务无优势。

6. 复现

bashcd ~/mujoco_ws
python3 cartpole/mpc_cartpole.py                 # 默认 PID
python3 cartpole/mpc_cartpole.py --controller mpc --headless 400
python3 cartpole/mpc_cartpole_qp.py              # 默认 QP-MPC
python3 cartpole/mpc_cartpole_qp.py --compare    # 三种抗扰对比

7. 要点总结（可迁移）

  • MPC 的四件套：测量 → 预测(H步) → 优化/采样选最优 → 只执行第一步。
  • 采样法简单但高维无效；线性 QP 精准、适合短视界；非线性用 CasADi+IPOPT（见 04_Go2_SRBD_MPC）。
  • 线性 MPC 的软肋：模型在平衡点外失准 + 短视界开环，遇到持续偏置会跑偏。

02Furuta（旋转倒立摆）：能量摆起 + LQR

比 CartPole 多一个维度：摆杆绕可旋转的臂摆动。目标：摆起 + 稳住 + 被打倒能自恢复。 代码：~/mujoco_ws/furuta/

1. 系统

  • 旋转臂（电机驱动）+ 摆杆（自由摆）。状态含臂角/角速度、摆角/角速度。
  • 难点：平衡点附近是倒立不稳定，需要先把能量“泵”上来（摆起），再 LQR 平衡。

2. 两条路线

文件 做法 结果
矮模型系列 靠“杆戳地/撞限位”辅助摆起 能起但不能自恢复
furuta_swingup.py 抬高模型 + 闭环泵能 + LQR 成品：既能摆起，又能被打倒后自恢复
mpc_furuta.py / furuta_lqr_mpc.py 能量法 + LQR / 平衡期 MPC 参考/实验
furuta_mpc.py 纯 MPC（CEM）摆起 未完全成功

3. 闭环泵能（关键）

能量法摆起：让系统总能量趋向倒立静止能量 E*，按能量差施加控制。 本项目的闭环泵能律（抬高模型）：

u = k · φ̇ · cos(φ) · clip((-E)/Esc, 0, 1)      # φ=摆角
参数：k=80, Esc=0.2
  • 只用“加能量”且按能量差自动收敛 → 摆起后自然停机交给 LQR。
  • 实测：803 步 / 1.61s 摆起；被 knock（20~150）打倒后能自己重新泵起并稳住。
  • 开环正弦（只能加不能减）会把杆打飞 → 弃用。

4. LQR 平衡

  • 线性化后求 Riccati 解，全状态反馈。
  • 参数（矮模型最优）：Q = [10, 50000, 1, 1]，R = 0.5。
  • 调参脚本：furuta/furuta_tune.py。

5. 经验总结

  1. 先摆起、再平衡：分阶段（能量摆起 → 切换 LQR），比端到端 MPC 稳。
  2. 泵能要闭环（按能量差），开环正弦不可控。
  3. 模型抬高消除了“靠戳地摆起”的病态依赖，才可能自恢复。
  4. LQR 是局部最优：只在平衡点附近有效，所以摆起阶段必须交给能量法。

6. 复现

bashcd ~/mujoco_ws
python3 furuta/furuta_swingup.py          # 成品：摆起 + 平衡（可 knock 测试）
python3 furuta/furuta_tune.py             # 调参
python3 furuta/furuta_lqr_mpc.py          # 能量 + LQR + 平衡期 MPC

7. 与 CartPole / Go2 的关系

  • 都是「不稳定平衡 + 反馈」范式；Furuta 多了“能量注入”这一层。
  • 这里的分阶段控制思想（摆起→平衡）也是后面 RL 多技能切换（walk↔getup）的直觉来源。

03Go2 站立与抗推：PD / LQR / MPC 对比

用 Unitree Go2 模型做「四脚站立 + 抗外力推」的经典控制实验，扫描增益、给出结论。 代码：~/mujoco_ws/go2/（go2_stand.py、go2_push_test.py、多个 *_sweep.py） 详细结论原文：go2/go2_结论.md

1. 任务与指标

  • 任务：Go2 站住；被推力 xfrc 推后能否恢复。
  • 恢复步数：推后回到稳态所需步数（下界 HOLD_STEPS=30 → 最快 29）。
  • survival/16：方向{+x,-x,+y,-y} × 力{300,600N} × 时长{0.1,0.3s} 中“能恢复”的个数。
  • ⚠️ survival 对力非单调（300N 能恢复、250N 反而倒）→ “临界推力二分法”不可用。

2. 三种控制器

  • PD（关节位置伺服）：τ = KP(q*−q) − KD·q̇。
  • LQR：线性化 + 全状态反馈。
  • 采样 MPC：随机采样/CEM 预测，选最优首步（同 CartPole 思路）。

3. 关键结论

  1. 采样 MPC 无益（此任务）：开环 + 视界太短(H=15, 0.03s) + 代价与“抗推”不对齐，300N 时甚至更差。
  2. LQR 受“不可控中性模态”限制： - 浮动基 + 脚踩地 → 基底水平平移电机改不了，闭环特征值钉在 ≈1（轻阻尼）； - 任何 Q/R 都压不下来，细调 Q/R 对鲁棒性几乎无提升（最好 4/16）； - 大冲击出线性区即失效。
  3. PD 最抗推：抗推主要由增益决定 - KD 越大越抗推（过大不稳）；KP:KD≈2:1 最优； - 甜区 KP≈300, KD≈150 → survival 13/16；机制：高 KP 使力矩常饱和(近似 bang-bang)、高 KD 强阻尼 → 机身像刚性块，靠宽支撑面扛冲击。
  4. 方向/时长强依赖：+x(前)最抗、-x/侧向最弱；短冲量(0.1s) ≫ 持续力(0.3s)。
  5. 重力前馈在浮动基上无效（机身重力由接触承担），反而更差。

4. 关键数字

控制器 100N 恢复步数 survival/16
PD 旧默认 60/3 238 2
PD 140/60 29 9
PD 300/150（现行默认） 29 13
LQR（最好配置） 29 4
MPC(LQR 底) 300N 204 / 倒 —

5. 现行设置

  • go2_stand.py：KP=300.0, KD=150.0，PD_FF=False（重力前馈默认关）。
  • --controller pd|mpc|lqr、--mpc-base pd|lqr。

6. 复现

bashcd ~/mujoco_ws/go2
python3 go2_stand.py                                   # 默认 PD(300/150)
python3 go2_stand.py --controller lqr
python3 go2_stand.py --controller mpc --mpc-base lqr
python3 go2_push_test.py --controller pd --headless --force 100   # 打印恢复步数
python3 go2_pd_sweep.py --force 100        # KP×KD 网格
python3 go2_lqr_fine.py                    # LQR Q/R 多方向 survival

窗口里双击身体后 Ctrl+右键施力可手动推。

7. 启示

  • “站着硬扛”对浮动基四足有上限；想更抗推需要主动迈步/接触切换（步态、全身控制 WBC/MPC、或 RL）——这正是后面 RL 的动机。
  • 结果仅限仿真（单点 xfrc 推力），真机还有摩擦/延迟/电机饱和。

04Go2 单刚体 MPC 与 VMC trot（实验）

进阶经典控制：把 Go2 当作单刚体做 MPC 求四足接触力，再映射成关节力矩；外加足端轨迹 + VMC 平衡的原地 trot。 代码：~/mujoco_ws/go2_mpc/{mpc_go2_srbd.py, go2_vmc_trot.py}

1. SRBD（单刚体动力学）MPC —— mpc_go2_srbd.py

思想：忽略腿的动力学，把整机当一个刚体；决策变量是四只脚的接触力，MPC 每拍解一次。

  • 状态 x（12 维）：位置(3) + 姿态 rpy(3) + 线速度(3) + 角速度(3)。
  • 控制 u（12 维）：4 腿 × 3 维足端力 f_FL,f_FR,f_RL,f_RR（世界系）。
  • 刚体动力学：v̇ = g + Σf/m，ω̇ = I⁻¹ Σ(r_i × f_i)。
  • 参数：m=15.2，I=[0.08,0.24,0.24]，视界 N=12，dt=0.03。
  • 代价：Qx = diag(50×3, 30×3, 200×3, 10×3)（位置/姿态/速度/角速度），Ru=1e-4。
  • 求解器：CasADi + IPOPT（非线性规划，ca.nlpsol('mpc','ipopt',...)）。
  • 输出：四脚接触力 → 用腿雅可比 τ = Jᵀ f 映射成关节力矩；摆动腿用足端 PD。

运行：

bashcd ~/mujoco_ws/go2_mpc
python3 mpc_go2_srbd.py --gait stand --time 5
python3 mpc_go2_srbd.py --gait trot --time 10 --view

2. VMC + 足端轨迹 trot —— go2_vmc_trot.py

分层：上层生成足端轨迹（支撑/摆动），腿 IK 求关节角，关节 PD 跟踪；再加一层 VMC（虚拟模型控制）平衡：用机身高度/姿态/速度误差去微调足端目标。 - 关键参数：Z_REF=0.25（机身参考高度）、T=0.5s（步态周期）。 - 摆动腿：足端走贝塞尔/正弦弧；支撑腿：足端相对机身向后推。 - VMC：足端目标 = 名义足端 + 由(高度误差, 姿态误差, 速度误差)生成的修正。

3. 踩过的坑（重要）

现象 原因 修法
腿抬不起来/翻倒 IK 少了 cdof / 未在 IK 前 mj_forward IK 前先 mj_forward，用正确自由度
整机不稳、垮塌 只有足端 PD，缺平衡反馈 加 VMC/平衡层（本项目未完全跑通）
原地 trot 变成扑腾/后溜 足端 z 挂在机身、无地面锁定；相位/符号错 足端锁地面高度 + 正确屈膝相位

4. 结论（诚实）

  • SRBD-MPC 能把接触力算出来并驱动，但手写整套稳定步态非常难（对象是浮动基 + 接触切换）。
  • VMC 能补一点平衡，但本项目未做到稳定 trot（和后面自建狗“手写 trot 也失败”是同一个难点）。
  • 这也是转向上 强化学习 的直接原因：接触/步态这种东西，用优化或 RL 端到端学，比手搭更省力。

5. 对比 RL 的取舍

经典（SRBD-MPC/VMC） 强化学习
可解释/可控 强（有模型） 弱（黑盒）
接触/步态 极难手调 擅长（端到端）
实时性 MPC 求解重 策略推理极轻（ONNX）
sim2real 依赖模型精度 靠域随机化
