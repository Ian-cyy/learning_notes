零为什么需要 TF2（10 分钟概念）

机器人身上有一堆坐标系：

map（地图）
 └ odom（里程计）
    └ base_link（车体）
       ├ camera_link（相机）
       ├ laser（雷达）
       └ arm_base → link1 → link2 → ... → gripper（机械臂链条）
  • TF2 = ROS2 的坐标变换系统：记录"谁相对谁、在哪、朝向如何"
  • 两种数据：静态 TF（装死的，如相机相对车体，发一次即可）+ 动态 TF（会动的，如机械臂关节，要持续发）
  • 两个角色：广播者（Broadcaster）发布变换；监听者（Listener）查询"A 到 B 怎么转"
  • 实际用途：相机看到的目标在 camera_link 下，要转到 base_link 才能让车去对准——你们 C70 项目的核心数学就是这个

一命令行先体验一把（不用写代码）

bash# 终端A：手动发一个静态 TF（world → base_link，抬到 z=1 米）
ros2 run tf2_ros static_transform_publisher --x 0 --y 0 --z 1 --yaw 0 --pitch 0 --roll 0 --frame-id world --child-frame-id base_link

ros2 run tf2_ros tf2_echo world base_link
# 看到 translation: [0, 0, 1] 就对了

二写一个静态 TF 广播节点

在 python_launch_demo 里新增 static_tf_demo.py：

pythonimport rclpy
from rclpy.node import Node
from tf2_ros import StaticTransformBroadcaster
from geometry_msgs.msg import TransformStamped


class StaticTfDemo(Node):
    def __init__(self):
        super().__init__('static_tf_demo')
        self.broadcaster = StaticTransformBroadcaster(self)

        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'base_link'          # 父
        t.child_frame_id = 'camera_link'         # 子
        t.transform.translation.x = 0.10         # 相机装在前方10cm
        t.transform.translation.y = 0.0
        t.transform.translation.z = 0.50         # 高50cm
        t.transform.rotation.w = 1.0             # 无旋转（单位四元数）
        self.broadcaster.sendTransform(t)
        self.get_logger().info('static tf: base_link -> camera_link 已发布')


def main():
    rclpy.init()
    node = StaticTfDemo()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

注册（setup.py 的 console_scripts）：

python'static_tf_demo = python_launch_demo.static_tf_demo:main',

验证：

bashcolcon build --symlink-install && source install/setup.bash
ros2 run python_launch_demo static_tf_demo
# 另开终端
ros2 run tf2_ros tf2_echo base_link camera_link
ros2 topic echo /tf_static --once
💡 要点
静态 TF 用 StaticTransformBroadcaster（发一次就够，latched）；frame_id=父、child_frame_id=子。

三动态 TF 广播（会动的）

新增 tf_mover.py：让 camera_link 绕 z 轴来回摆：

pythonimport math

import rclpy
from rclpy.node import Node
from tf2_ros import TransformBroadcaster
from geometry_msgs.msg import TransformStamped


class TfMover(Node):
    def __init__(self):
        super().__init__('tf_mover')
        self.br = TransformBroadcaster(self)
        self.t = 0.0
        self.create_timer(0.1, self.tick)        # 10Hz

    def tick(self):
        self.t += 0.1
        yaw = 0.6 * math.sin(self.t)             # 摆动 ±0.6 rad

        msg = TransformStamped()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.header.frame_id = 'base_link'
        msg.child_frame_id = 'camera_link'
        msg.transform.translation.x = 0.10
        msg.transform.translation.z = 0.50
        msg.transform.rotation.z = math.sin(yaw / 2)   # 绕 z 的四元数
        msg.transform.rotation.w = math.cos(yaw / 2)
        self.br.sendTransform(msg)


def main():
    rclpy.init()
    node = TfMover()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

验证：

bashros2 run python_launch_demo tf_mover
ros2 run tf2_ros tf2_echo base_link camera_link    # 数值在动
💡 要点
动态 TF 必须持续发（10Hz 以上）；每帧带时间戳。

四TF 监听（查询变换，★最实用）

新增 tf_listener.py：

pythonimport rclpy
from rclpy.node import Node
from rclpy.time import Time
from tf2_ros import Buffer, TransformListener


class TfListener(Node):
    def __init__(self):
        super().__init__('tf_listener')
        self.buffer = Buffer()
        self.listener = TransformListener(self.buffer, self)
        self.create_timer(1.0, self.tick)

    def tick(self):
        try:
            t = self.buffer.lookup_transform('base_link', 'camera_link', Time())
            tr = t.transform.translation
            self.get_logger().info(f'相机在车体系: x={tr.x:.3f} y={tr.y:.3f} z={tr.z:.3f}')
        except Exception as e:
            self.get_logger().warn(f'查询失败: {e}')


def main():
    rclpy.init()
    node = TfListener()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

实战意义：把相机里检测到的目标点转到车体系

这正是你们项目的需求：

python# 相机系下目标点 (x_c, y_c, z_c) → 车体系
# 1) 构造 PointStamped(frame_id='camera_link')
# 2) buffer.transform(point, 'base_link') 一行搞定
💡 要点
Buffer 缓存一段时间的历史；lookup_transform 可能抛异常（超时/不存在）——必须 try/except。

五URDF（机器人模型）

URDF 用 XML 描述机器人：link（刚体）+ joint（关节）。

写一个两连杆小臂 urdf/two_link_arm.urdf：

xml<?xml version="1.0"?>
<robot name="two_link_arm">
  <link name="base_link">
    <visual>
      <geometry><cylinder radius="0.05" length="0.02"/></geometry>
      <origin xyz="0 0 0.01"/>
    </visual>
  </link>

  <joint name="joint1" type="revolute">
    <parent link="base_link"/>
    <child link="link1"/>
    <origin xyz="0 0 0.02"/>            <!-- 相对父坐标系 -->
    <axis xyz="0 1 0"/>                 <!-- 绕 y 轴转 -->
    <limit lower="-1.57" upper="1.57" effort="10" velocity="1.0"/>
  </joint>

  <link name="link1">
    <visual>
      <geometry><box size="0.02 0.02 0.30"/></geometry>
      <origin xyz="0 0 0.15"/>          <!-- 视觉几何居中 -->
    </visual>
  </link>

  <joint name="joint2" type="revolute">
    <parent link="link1"/>
    <child link="link2"/>
    <origin xyz="0 0 0.30"/>
    <axis xyz="0 1 0"/>
    <limit lower="-1.57" upper="1.57" effort="10" velocity="1.0"/>
  </joint>

  <link name="link2">
    <visual>
      <geometry><box size="0.02 0.02 0.25"/></geometry>
      <origin xyz="0 0 0.125"/>
    </visual>
  </link>
</robot>
💡 要点
  • joint 的 origin 是相对 parent link 的（不是世界）
  • visual/origin 是几何体自身在 link 坐标系里的位置（常用来把几何"居中"）
  • 关节类型：revolute（限位旋转）/ continuous / prismatic / fixed

六robot_state_publisher + joint_state_publisher_gui + RViz2

原理：joint_state_publisher_gui 发关节角 → robot_state_publisher 算 TF → RViz2 显示模型。

写 launch/06_urdf.launch.py：

pythonimport os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    urdf_path = os.path.join(
        get_package_share_directory('python_launch_demo'),
        'urdf', 'two_link_arm.urdf')
    robot_description = {'robot_description': open(urdf_path).read()}

    return LaunchDescription([
        Node(package='robot_state_publisher', executable='robot_state_publisher',
             parameters=[robot_description], output='screen'),
        Node(package='joint_state_publisher_gui', executable='joint_state_publisher_gui',
             output='screen'),
        Node(package='rviz2', executable='rviz2', output='screen'),
    ])

urdf 目录也要在 setup.py 注册：

python(os.path.join('share', package_name, 'urdf'), glob('urdf/*.urdf')),

九踩坑清单

坑说明
frame_id / child_frame_id 写反父在前、子在后
静态 TF 用了普通 Broadcaster静态必须用 StaticTransformBroadcaster（发一次）
动态 TF 忘了持续发监听端会报 "extrapolation into the future" / 查不到
时间戳用 self.get_clock().now().to_msg()，别用 0
lookup_transform 抛异常必须 try/except（启动初期 TF 还没到）
URDF joint origin 理解错是相对父 link，不是世界坐标
RViz Fixed Frame 没设设成 TF 树里存在的（如 base_link），否则一片空白
RobotModel 的 Description Topic 没选展开 RobotModel → 选 /robot_description，否则模型不显示
view_frames 报错装 graphviz
TF 树有多个父每个坐标系只能有一个父，冲突会导致查询失败
没 source install每开新终端都要 source install/setup.bash

十学完自测（含答案）

自测题参考答案
能说出静态 TF 和动态 TF 的区别与各自用法？ 静态 TF：安装关系固定不变（如相机相对车体）→ StaticTransformBroadcaster 发一次（latched），数据在 /tf_static；动态 TF：随时间变化（关节角、里程计）→ TransformBroadcaster 定时器持续发（≥10Hz），每帧带时间戳，数据在 /tf。两者查询方式相同。
会写广播者（静态/动态）和监听者？ 静态：StaticTransformBroadcaster(self).sendTransform(t) 只发一次；动态：TransformBroadcaster(self) + create_timer(0.1, tick) 里反复发；监听：Buffer() + TransformListener(buffer, self)，查询 buffer.lookup_transform('父','子',Time())。查询必须 try/except（TF 还没到会抛异常）。
会用 tf2_echo / view_frames / RViz 排查 TF 问题？ tf2_echo 父 子 查变换（数值变化=动态）；view_frames 生成 frames.pdf 看整棵 TF 树（需 graphviz）；RViz 里设 Fixed Frame + TF/RobotModel 显示。查不到 = 没有对应的 TF 发布（检查广播节点是否在跑）。
能读懂 URDF 的 link/joint/origin/axis/limit？ link=刚体（visual/collision/inertial）；joint=关节（parent/child/origin/axis/limit/type）；origin 是相对父 link 的位姿，不是世界坐标；axis=旋转轴；limit=角度范围（revolute 必需）。
能跑起 robot_state_publisher + gui + RViz 三件套？ robot_state_publisher（parameters=[{'robot_description': open(urdf).read()}]）+ joint_state_publisher_gui（滑条发 /joint_states）+ rviz2；setup.py 注册 urdf 目录；RViz：Fixed Frame → base_link、Add RobotModel、Description Topic 选 /robot_description。
会用 buffer.transform 把点从一个坐标系转到另一个？ 构造 PointStamped（frame_id='camera_link'）→ buffer.transform(点, 'base_link') 一行转换；转换前确保两坐标系间有 TF 链（先用 tf2_echo 验证）。
理解"关节角 → TF → 末端位姿"就是 FK？ 关节角（/joint_states）→ robot_state_publisher 按 URDF 关节链算出每个 link 的 TF → 末端 link 相对 base_link 的变换就是正运动学（FK）结果；RViz 只是把它画出来。可与手算 FK 对比验证。
